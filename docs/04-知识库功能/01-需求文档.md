# 知识库功能需求文档（PRD）

> 创建日期：2026-06-01  
> 状态：待评审  
> 版本：1.0

---

## 一、背景与目标

### 1.1 背景

当前系统支持 LLM 对话、沙箱执行、记忆系统等功能，但缺乏对外部知识库的检索能力。用户希望 Agent 能够访问企业内部文档、产品手册、技术文档等专业知识，以提供更准确的回答。

RAGFlow 是一个成熟的开源 RAG 框架，提供了标准化的 `/dify/retrieval` 检索接口，适合作为知识库后端进行集成。

### 1.2 目标

- 支持对接 RAGFlow 知识库系统
- 支持在管理后台配置 RAGFlow 全局连接信息
- 支持管理多个知识库资源
- 支持为不同 Agent 绑定不同的知识库
- Agent 在对话中可自动检索知识库内容，增强回答准确性

---

## 二、用户角色

| 角色 | 权限 | 说明 |
|------|------|------|
| 管理员 | 配置 RAGFlow、管理知识库、配置 Agent | 系统管理员，负责知识库的接入和配置 |
| 普通用户 | 使用 Agent 对话 | 与已配置知识库的 Agent 进行对话 |

## 三、功能需求

### 3.1 RAGFlow 全局配置

**功能描述**：管理员可在后台配置 RAGFlow 服务的全局连接信息。

**配置项**：
- **服务地址（base_url）**：RAGFlow 服务的访问地址（如 `http://localhost:9380`）
- **API 密钥（api_key）**：用于认证访问 RAGFlow 的 API Key

**用户故事**：
> 作为管理员，我希望能配置 RAGFlow 服务的连接信息，以便系统能够访问 RAGFlow 知识库。

**验收标准**：
- 管理员可在管理后台查看和编辑 RAGFlow 配置
- 配置保存后，所有知识库检索请求使用该配置
- 配置变更立即生效，无需重启服务
- API 密钥在界面上脱敏显示

---

### 3.2 知识库资源管理

**功能描述**：管理员可管理系统中的知识库资源，每个知识库对应 RAGFlow 中的一个数据集。

**知识库属性**：
- **名称**：知识库的显示名称
- **数据集 ID（dataset_id）**：RAGFlow 中的数据集标识
- **描述**：知识库的内容描述（帮助系统判断何时使用该知识库）
- **启用状态**：是否启用该知识库

**用户故事**：
> 作为管理员，我希望能添加、编辑、删除知识库，以便管理不同类型的知识资源。

**验收标准**：
- 管理员可创建新知识库，填写名称、数据集 ID、描述
- 管理员可编辑已有知识库的信息
- 管理员可删除知识库（删除前需确认，删除后自动解除与所有 Agent 的绑定）
- 管理员可启用/禁用知识库（禁用的知识库不会被检索）
- 管理员可测试知识库连接（验证 RAGFlow 配置和数据集 ID 是否有效）

---

### 3.3 Agent 知识库绑定

**功能描述**：管理员可为每个 Agent 绑定一个或多个知识库，使 Agent 在对话时能够检索这些知识库的内容。

**用户故事**：
> 作为管理员，我希望能不同的 Agent 绑定不同的知识库，以便提供专业化的知识服务。

**示例场景**：
- "客服 Agent" 绑定"产品手册"和"常见问题"知识库
- "技术 Agent" 绑定"API 文档"和"故障排查"知识库
- "通用 Agent" 不绑定任何知识库

**验收标准**：
- 在 Agent 配置页面，管理员可选择绑定多个知识库
- 管理员可解除 Agent 与知识库的绑定
- 绑定关系保存后立即生效
- 未绑定知识库的 Agent 不会显示知识库检索工具

---

### 3.4 Agent 对话中的知识库检索

**功能描述**：当用户与已绑定知识库的 Agent 对话时，Agent 可自动检索知识库内容，并将相关信息作为上下文辅助回答。

**用户故事**：
> 作为普通用户，我希望 Agent 能够参考知识库中的信息回答我的问题，以便获得更准确、更专业的答案。

**示例对话**：

**用户**：如何配置 SMTP 邮件服务？

**Agent**（内部自动检索知识库，找到相关文档片段）：

**Agent**（回答）：根据产品手册，配置 SMTP 邮件服务的步骤如下：
1. 进入"系统设置" > "邮件配置"
2. 填写 SMTP 服务器地址、端口、用户名、密码
3. 点击"测试连接"验证配置
4. 保存配置

**验收标准**：
- Agent 在需要时可自动调用知识库检索工具
- 检索结果作为上下文提供给 Agent，辅助生成回答
- 检索失败时，Agent 应优雅降级，不影响正常对话
- 用户无需感知知识库检索的过程（由 Agent 自动决定）

---

## 四、非功能需求

### 4.1 性能

- 知识库检索响应时间应控制在 5 秒以内
- 支持并发检索多个知识库

### 4.2 可用性

- RAGFlow 服务不可用时，不影响 Agent 的其他功能
- 检索失败时应记录日志，便于排查问题

### 4.3 安全性

- API 密钥应加密存储
- 知识库检索应遵循多租户隔离原则

## 五、界面设计要点

### 5.1 知识库管理页面

**入口**：管理后台侧边栏 → "知识库"

**页面布局**：
- 顶部：RAGFlow 全局配置卡片（服务地址、API 密钥、保存按钮）
- 主体：知识库列表（卡片式布局，每张卡片显示名称、数据集 ID、描述、启用状态、操作按钮）
- 右上角：添加知识库按钮

**创建/编辑对话框**：
- 名称输入框（必填）
- 数据集 ID 输入框（必填）
- 描述文本框（选填）
- 启用开关
- 测试连接按钮
- 保存/取消按钮

### 5.2 Agent 配置侧边栏

**位置**：Agent 配置页面 → 侧边栏

**新增区块**："知识库配置"（位于"MCP 服务"之后）

**交互方式**：
- 显示已绑定的知识库列表
- 提供"添加知识库"按钮，弹出选择对话框
- 支持解除绑定

## 六、术语表

| 术语 | 说明 |
|------|------|
| RAGFlow | 开源的 RAG（检索增强生成）框架 |
| 知识库（Knowledge Base） | 系统中管理的知识资源单元 |
| 数据集（Dataset） | RAGFlow 中的文档集合，对应一个知识库 |
| 检索（Retrieval） | 从知识库中查找与问题相关的文档片段 |
| RAG | 检索增强生成（Retrieval-Augmented Generation），通过检索外部知识来增强 LLM 回答 |
