# Hook 机制技术方案

> 日期：2026-08-08
> 对应《01-需求文档.md》，说明实现要点：事件注册表、HookManager 调度、webhook / 沙箱命令动作执行、递归防护、安全、数据模型、接口、埋点清单与实施计划。

## 1. 架构总览

```
  AgentLoop.run() / ToolExecutor / core/context.py
                       │  hook_manager.fire(event, ctx, data)  ← 只入队，不等待
                       ▼
        ┌─────────────────────────────────────────┐
        │ hooks/manager.py  HookManager           │
        │  - 匹配（global/tenant/agent 三级作用域） │
        │  - 有界队列 (maxsize=queue_size)          │
        └──────────────────┬──────────────────────┘
                           │  worker × N (asyncio)
        ┌──────────────────┼──────────────────────┐
        ▼                  ▼                      ▼
   dispatcher.webhook  dispatcher.sandbox_command  hooks/dispatcher.py
   (httpx POST+签名)   (SandboxManager.execute)      │
        │                  │                        │
        └──────────────────┴────────────────────────┘
                           │ 写 hook_executions（批写队列）
                           ▼
                   /api/hook-executions → 前端 /hooks
```

设计要点（对齐现有 `observation/recorder.py` 的成熟模式）：
- **埋点只入队、不等待**：`fire()` / `fire_nowait()` 把匹配到的 Hook 塞进有界队列立即返回，动作执行与日志写入全在后台 worker，Agent 主流程（SSE 流）零阻塞。
- **有界队列防风暴**：高并发事件（PreToolUse/PostToolUse）或外部抖动时不至于无限堆积；队列满则丢弃并告警（同 recorder 的 `QueueFull` 处理）。
- **失败静默**：动作超时/网络错误/命令非 0 退出码只记入 `hook_executions`，绝不抛回 Agent。

## 3. 事件注册表与负载

`events.py` 集中声明，事件字典（管理端表单/说明）直接由注册表驱动：

```python
@dataclass(frozen=True)
class EventDef:
    name: str
    description: str
    payload_fields: tuple[tuple[str, str, bool], ...]  # (字段, 说明, 是否含敏感值需脱敏)

EVENTS: dict[str, EventDef] = {e.name: e for e in [
    EventDef("SessionStart", "会话开始", ...),
    EventDef("SessionEnd", "会话结束", ...),
    EventDef("PreToolUse", "工具调用前", ...),
    EventDef("PostToolUse", "工具调用后", ...),
    EventDef("PreCompact", "上下文压缩前", ...),
    EventDef("PostCompact", "上下文压缩后", ...),
    EventDef("Notification", "异常事件", ...),
]}
```

统一负载（所有事件共享外壳，`data` 随事件变化）：

```json
{
  "event": "PostToolUse",
  "event_id": "uuid4",
  "timestamp": "2026-08-08T12:00:00Z",
  "trace_id": "…", "session_id": "…", "user_id": "…",
  "tenant_id": "…", "agent_id": "…", "model": "…",
  "hook": {"id": "…", "name": "…", "scope": "agent"},
  "data": { }
}
```

**各事件 data 字段**：

| 事件 | data 字段 | 说明 |
|---|---|---|
| SessionStart | `user_input`（截断 500）`model` `max_iterations` `trust_level` | 会话起点 |
| SessionEnd | `status`（completed/timeout/error）`duration_ms` `iteration_count` `tool_call_count` `total_tokens` `hit_max_iterations` `final_output`（截断 500） | 会话终点 |
| PreToolUse | `tool_name` `exec_type` `arguments`（脱敏）`is_delegation` `is_ask_user` | 工具调用前 |
| PostToolUse | `tool_name` `exec_type` `success` `error_type` `duration_ms` `output_excerpt`（截断 500）`is_truncated` | 工具调用后 |
| PreCompact | `tokens_before` `budget_usable` `compress_threshold` | 压缩前 |
| PostCompact | `tokens_before` `tokens_after` `saved_tokens` `summary_tokens` `is_emergency` | 压缩后 |
| Notification | `level`（permission/error/warning）`category`（permission_denied / context_high_utilization / max_iterations / tool_error）`message` `extra` | 异常通知 |

外壳字段从 `ObsContext`（`observation/recorder.py` 的 `get_obs_context()`）读取；`model` 缺省留空。若 ObsContext 缺失（如后台定时任务压缩路径），**只匹配 global 作用域 Hook**，外壳上下文字段置空。

## 4. HookManager：匹配与调度

### 4.1 匹配规则

`fire(event, *, data)` 时遍历已加载的启用 Hook，命中条件：

| 作用域 | 命中条件 |
|---|---|
| global | 恒命中 |
| tenant | `hook.tenant_id == ctx.tenant_id` |
| agent | `hook.agent_id == ctx.agent_id` |

同事件多 Hook **全部触发**（互不覆盖），worker 各自独立执行。

### 4.2 队列与 worker

```python
class HookManager:
    def __init__(self):
        self._queue: asyncio.Queue[HookTask] = asyncio.Queue(maxsize=settings.hook.queue_size)
        self._workers: list[asyncio.Task] = []
        self._sandbox_mgr: SandboxManager | None = None

    def start(self, sandbox_mgr) -> None:
        self._sandbox_mgr = sandbox_mgr
        for _ in range(settings.hook.concurrency):
            self._workers.append(asyncio.create_task(self._worker_loop()))

    def fire_nowait(self, event, *, data=None, **ctx) -> None:   # 同步入口，直接 put_nowait
        ...  # 匹配 + put_nowait；QueueFull → 丢弃 + 告警日志

    async def fire(self, event, *, data=None, **ctx) -> None:    # 异步入口，put 不阻塞
        ...
```

`fire_nowait` 供**同步调用点**（`AgentLoop._finalize_trace`、`finalize_trace_error`）使用；`fire` 供异步调用点使用。二者都只做匹配 + 入队，不做任何网络/DB 操作。

### 4.3 worker

```python
async def _worker_loop(self) -> None:
    while True:
        task = await self._queue.get()
        try:
            result = await dispatcher.execute(task.hook, task.payload)   # 含超时/重试
        finally:
            await self._write_log(task, result)    # 批写 hook_executions
```

worker 数量与队列大小见 §8 配置项。

## 5. 动作执行（dispatcher.py）

`dispatcher.execute(hook, payload)` 按 `action_type` 分发，统一套用：脱敏 → 超时（`timeout_ms`）→ 失败重试（`retry_count`，指数退避 1s/2s）。

### 5.1 webhook

```python
async def _webhook(hook, payload) -> ActionResult:
    url = hook.config["url"]
    validate_url(url)                                   # §7 SSRF 防护
    body = json.dumps(payload, ensure_ascii=False).encode()
    headers = {**hook.config.get("headers", {})}
    if hook.config.get("sign"):
        headers["X-Hook-Signature"] = sign_hook(body, hook.config["secret"])
    async with httpx.AsyncClient(timeout=timeout) as client:
        resp = await client.post(url, content=body, headers=headers)
    # status 2xx → success，否则 failed（附 http_status）
```

- 签名算法：`HMAC-SHA256(body, secret)`，hex 小写，放 `X-Hook-Signature` 头（`signing.py`）。
- `secret` 存入 hooks.config，**API 返回时脱敏**（`{"sign":true}` 不回显明文）。
- 事件元信息额外以 `X-Hook-Event: <event>` 头透出，便于外部系统识别。

### 5.2 sandbox_command

```python
async def _sandbox_command(hook, payload, ctx) -> ActionResult:
    cmd = render_template(hook.config["command"], payload)       # {{session_id}} 等占位符
    sandbox = await self._sandbox_mgr.get_or_create(
        user_id=ctx["user_id"], session_id=ctx["session_id"],
        workspace_id=ctx.get("workspace_id") or ctx["user_id"],
        workspace_slug=ctx.get("workspace_slug") or "default",
    )
    # 先写入负载 JSON，再执行用户命令
    b64 = base64.b64encode(json.dumps(payload).encode()).decode()
    full = f"echo '{b64}' | base64 -d > /tmp/hook_payload.json && {cmd}"
    result = await self._sandbox_mgr.execute(sandbox, full, timeout=timeout_s)
    return ActionResult(status="success" if result.exit_code == 0 else "failed",
                        exit_code=result.exit_code, error=result.stderr or None)
```

- 负载经 **base64** 写入容器 `/tmp/hook_payload.json`，避免 shell 转义/注入；命令模板可引用该文件（如 `python3 -c "import json;d=json.load(open('/tmp/hook_payload.json'))"`）。
- 命令在沙箱容器内、`sandbox` 用户下执行（`SandboxManager.execute` 已固定 workdir=/workspace），受沙箱网络与权限限制，不接触宿主机。
- `workspace_id` / `workspace_slug` 由调用点（AgentLoop 内的 `ToolContext`）透传；缺失时回退 `user_id` / `"default"`。

### 5.3 结果

`ActionResult`：`status`（success / failed / timeout / skipped）、`duration_ms`、`http_status` / `exit_code`、`error`、`response_preview`。worker 写日志 + 归集到观测体系（见 §6.4）。

## 6. 递归防护与并发控制

| 机制 | 做法 |
|---|---|
| 有界队列 | 队列满即丢（`fire_nowait` 处 log warning），从总量上封顶在途 Hook |
| 任务内递归阻断 | 新增 contextvars `hook_action_ctx`：worker 执行动作前 `set()`，`AgentLoop.run()` 入口检测到该标志时**跳过本次执行的 Hook 触发**（直接命中"hook 动作 → 再跑 Agent → 又触发 hook"的链式循环） |
| 事件幂等提示 | 负载含 `event_id`，文档约定外部集成按其幂等；`hook.id` 供日志归因 |
| 并发上限 | `concurrency` 个 worker 即为全局并发上限（默认 4） |

## 7. 安全设计

| 风险 | 实现 |
|---|---|
| SSRF | `validate_url`：用 `urllib.parse` + `socket.getaddrinfo` 解析 host，拒绝环回/链路本地/私网地址（`ipaddress.is_private` 等）；`HOOK_ALLOW_PRIVATE_URLS=true` 可显式放开。可选 `HOOK_URL_ALLOWLIST` 域名白名单（逗号分隔，非空则仅允许白名单域名）。 |
| 请求伪造 | HMAC-SHA256 签名（§5.1）；secret 存库、API 不回显。 |
| 敏感数据泄露 | `masking.py` 在**入队前**对负载 `arguments`/`headers` 中 `password`/`token`/`api_key`/`secret`/`authorization` 键做打码（`***`）；日志中命令/响应 preview 一律用脱敏后数据。 |
| 命令注入/逃逸 | 命令只在沙箱内执行；负载经 base64 写入文件而非 shell 拼接；`SandboxManager.execute` 已限制 `sandbox` 用户 + `/workspace` workdir。 |
| 越权 | 所有 hooks 接口按作用域 + `tenant_id` + `visibility` 过滤；`global` 作用域的读写接口仅 `is_superuser`；日志查询仅本租户。 |
| 递归风暴 | 见 §6。 |

## 8. 配置项

新增 `core/config.py::HookSettings`（挂到 `AppSettings`）：

```python
class HookSettings(BaseSettings):
    model_config = SettingsConfigDict(env_prefix="HOOK_")
    enabled: bool = True
    queue_size: int = 2048                # 有界队列容量
    concurrency: int = 4                  # worker 并发数
    action_timeout_ms: int = 5000         # 默认动作超时（1-30000）
    max_retries: int = 1                  # 失败重试次数（0-3）

    max_payload_bytes: int = 1_000_000    # webhook body 上限
```

## 9. 数据模型与迁移

新增 `hooks` / `hook_executions` 两张表（`db/models.py`，沿用无外键 + `tenant_id`/`created_by` 风格），alembic 迁移：

```
hooks
  id UUID PK
  tenant_id UUID NULL          -- global 作用域为 NULL
  created_by UUID
  name String(128)
  description Text NULL
  scope String(16)             -- global / tenant / agent
  agent_id UUID NULL           -- scope=agent 必填
  event String(64)             -- 事件名（EVENTS 键）
  action_type String(16)       -- webhook / sandbox_command
  config JSONB                 -- {url, headers, secret, sign} | {command, workdir}
  timeout_ms Int               -- 默认 5000，1-30000
  retry_count Int              -- 默认 1，0-3
  is_enabled Bool
  visibility String(16)        -- tenant / private（仅 tenant/agent）
  created_at / updated_at timestamptz
  索引 (tenant_id, event), (agent_id, event), (scope)

hook_executions
  id UUID PK
  hook_id UUID
  event / scope String(16)
  trace_id / session_id / user_id / tenant_id / agent_id UUID NULL
  action_type String(16)
  target String(512)           -- URL 或命令（脱敏后的占位形式）
  status String(16)            -- success / failed / timeout / skipped
  duration_ms Int
  http_status Int NULL
  exit_code Int NULL
  error Text NULL
  response_preview Text NULL
  created_at timestamptz
  索引 (tenant_id, created_at), (hook_id, created_at)
```

**日志量控制**：`PreToolUse` / `PreCompact` 默认不落日志（`log_pre_events=false`），避免每工具一次的高频写放大；`PostToolUse` 高频场景可后续加采样。测试触发记录 `status=skipped` 前的模拟执行。

## 11. 埋点清单（代码位置）

> 原则：埋点只做 `fire`/`fire_nowait`（入队），不引入额外查询；数据尽量从已在手头的对象取。

| 事件 | 埋点位置 | 备注 |
|---|---|---|
| SessionStart | `core/agent.py::AgentLoop.run()` 构建 messages 后 | 异步 `fire` |
| SessionEnd | `core/agent.py::AgentLoop._finalize_trace()`（同步，覆盖 completed/timeout 两路径）；`finalize_trace_error()`（error 路径） | 同步 `fire_nowait`；data 用 `_finalize_trace` 已算好的 status/iteration/token/duration |
| PreToolUse / PostToolUse | `tools/executor.py::ToolExecutor.execute()` 外层包装（唯一入口，覆盖 sandbox/direct/mcp/remote/AskUserQuestion/delegation/权限拒绝全路径） | 执行前 `fire`，返回前 `fire`；`exec_type`/`error_type` 复用已有 `_exec_type`/`_error_type` |
| PreCompact / PostCompact | `core/context.py::compress_early_tool_results` 调用处（`agent.py` 内 step>3 分支）；`core/context.py::prepare_context` 压缩路径（budget 超限处） | 前者在 `run()` 内 ObsContext 已设；后者 ObsContext 可能缺失 → 仅 global Hook 命中（§3 规则） |
| Notification | `agent.py`：上下文 >90% 告警处、max_iterations 处、`tool_permission_denied` 处；`executor.py`：工具失败兜底处 | `category` 区分来源 |

> 委派子 Agent 复用同一套埋点：子 Agent 的 `AgentLoop.run()` 同样 set ObsContext（带各自 agent_id），hooks 自动按子 Agent 的 tenant/agent 命中。
