> 创建日期：2026-08-07
> 状态：待评审
> 版本：1.0

---

## 一、背景与目标

### 1.1 背景

平台目前的 Agent 执行对**外部系统是"黑盒"**：会话开始、工具调用、上下文压缩、执行结束这些关键节点，外部无法自动感知或介入。现有的集成手段都是"Agent 主动发起"：

| 现有手段 | 方向 | 局限 |
|---|---|---|
| 飞书渠道 | 对话通道 | 只能聊，不能感知生命周期事件 |
| 远程工具（REST 映射） | Agent → 外部 | 由 Agent 决定何时调用，外部被动响应 |
| MCP | Agent → 外部 | 同上，均为"拉"而非"推" |
| 可观测性（18 号模块） | 内部采集 | 数据落在平台内部，外部系统拿不到 |

缺少一种**事件驱动、由平台主动推送**的机制：例如"工具执行失败时通知企微""写文件后自动跑 lint""上下文快满时告警"。

### 1.2 参考

参考 Claude Code 的 Hooks 机制：在会话生命周期（SessionStart / SessionEnd、PreToolUse / PostToolUse、PreCompact / PostCompact、Notification）挂载用户自定义命令，实现自动化治理与集成。

### 1.3 目标

- 提供统一的 **Hook 配置模型**：事件 → 动作，支持平台级配置与管理
- 支持两类动作：**HTTP Webhook**（跨系统推送）与**沙箱命令**（工作区自动化）
- 支持**全局 / 租户 / Agent 三级作用域**，覆盖平台治理与单 Agent 定制
- 触发**异步非阻塞**，Hook 失败/超时不影响 Agent 主流程与对话
- 提供**触发日志与测试触发**，可观测、可排查
- 保证安全：SSRF 防护、请求签名、敏感字段脱敏、命令隔离在沙箱

## 二、用户角色

| 角色 | 权限 | 说明 |
|------|------|------|
| 平台管理员 | 配置**全局** Hook、查看全部触发日志 | 平台级治理（告警、审计、成本控制） |
| 租户管理员 | 配置**租户级** Hook、查看本租户日志 | 租户级集成与治理 |
| Agent 创建者 | 配置自己 Agent 的 **Agent 级** Hook | 单 Agent 定制行为 |

权限沿用现有模型：Hook 资源按 `tenant_id` + `visibility`（tenant/private）+ `created_by` 做应用层隔离，不引入新的权限体系。**全局级 Hook 仅平台管理员可管理**（`is_superuser` 判定，复用现有管理员判定）。

## 三、概念模型

### 3.1 事件（Event）

Hook 绑定的生命周期节点。事件定义与 Agent 执行循环 `AgentLoop.run()`（`core/agent.py`）一一对应：

| 事件 | 触发点 | 负载要点 |
|---|---|---|
| `SessionStart` | `run()` 入口，构建 messages 之后 | 输入、模型、max_iterations |
| `SessionEnd` | `run()` 正常返回 / 超迭代 / 异常终止 | 状态、耗时、总 token、迭代数、工具数 |
| `PreToolUse` | 每次工具调用执行前（`_execute_tool_traced` 内、`ToolExecutor.execute` 前） | 工具名、参数、执行类型 |
| `PostToolUse` | 每次工具执行完成后 | 工具名、成功与否、错误类型、耗时、输出（截断） |
| `PreCompact` | 上下文压缩执行前 | 压缩前 token |
| `PostCompact` | 压缩完成后 | 压缩前/后 token、节省量、摘要 token |
| `Notification` | 异常事件：权限拒绝、工具失败、上下文超 90%、超迭代上限 | 级别、消息、上下文 |

> 事件集中定义在 Hook 注册表（`hooks/events.py`），每个事件声明其 `name`、`description`、`payload_fields`，供管理端事件字典与创建表单使用。

### 3.2 动作（Action）

Hook 被触发时执行的动作，二选一：

| 动作类型 | 说明 | 适用场景 |
|---|---|---|
| `webhook` | POST JSON 到配置的 URL，支持自定义 Headers、HMAC 签名、超时 | 跨系统通知（企微/飞书）、对接外部 CI / 监控 |
| `sandbox_command` | 在用户沙箱容器内执行一条命令，事件 JSON 通过 **stdin** 传入，捕获 stdout/stderr | 工作区自动化（写文件后跑 lint、自动 git 提交、生成报告） |

> 命令在**沙箱容器**内执行（复用 `SandboxManager`，`tools/executor.py` 的沙箱调度），不接触宿主机，天然满足多租户隔离。

### 3.3 作用域（Scope）

| 作用域 | 生效范围 | 管理端可见性 |
|---|---|---|
| `global` | 全平台所有 Agent | 仅平台管理员 |
| `tenant` | 租户内所有 Agent | 租户管理员 |
| `agent` | 仅指定 Agent | Agent 创建者 |

**合并规则**：一个事件触发时，**同一作用域链上所有启用的匹配 Hook 全部执行**（global + tenant + agent 并行触发，互不覆盖）；`agent` 作用域 Hook 未命中该 Agent 时跳过。

## 四、功能需求

### 4.1 Hook 配置管理

**功能描述**：管理员/创建者可按作用域创建、编辑、启停、删除 Hook。

**Hook 属性**：
- **名称 / 描述**：标识与说明
- **作用域**：global / tenant / agent（agent 需选目标 Agent）
- **事件**：单选一个事件（多事件可建多条，不设计一对多，保持配置简单）
- **动作类型**：webhook / sandbox_command
- **启用状态**：是否参与触发
- **超时**：单次动作超时（默认 5s，上限 30s）
- **重试策略**：失败重试次数（默认 1，可选 0）

**动作参数（按类型区分）**：
- **webhook**：URL、自定义 Headers（JSON）、签名密钥（secret，可选）、是否启用签名
- **sandbox_command**：命令模板（占位符 `{{event}}` / `{{session_id}}` 等可选）、执行前是否设置工作目录

**验收标准**：
- 可 CRUD 各作用域 Hook，删除前二次确认
- 启停即时生效（下次触发不再执行）
- 同一事件可配置多个 Hook，合并触发
- 非本人/非本租户的 Hook 不可见、不可改

### 4.2 事件触发与执行

**功能描述**：Agent 执行到事件点时，HookManager 收集匹配的 Hook 并异步执行。

**执行语义**：
- **异步非阻塞**：Hook 通过 asyncio 后台任务执行，`fire()` 不等待动作完成（或等待但设超时上限），不阻塞 Agent 主循环的 SSE 流
- **上下文注入**：触发时从 `ObsContext`（`observation/recorder.py`）读取 trace_id / session_id / user_id / tenant_id / agent_id，与事件数据一起组成负载
- **失败静默**：Hook 超时 / 网络错误 / 命令失败只记入触发日志，不影响对话
- **递归防护**：Hook 动作产生的新会话/工具调用不再触发 Hook（执行上下文带 `is_hook_triggered` 标志），防止死循环

**统一负载结构（JSON）**：

```json
{
  "event": "PostToolUse",
  "event_id": "uuid",
  "timestamp": "2026-08-07T12:00:00Z",
  "trace_id": "…",
  "session_id": "…",
  "user_id": "…",
  "tenant_id": "…",
  "agent_id": "…",
  "model": "…",
  "scope": "agent",
  "hook_id": "…",
  "data": { }
}
```

**验收标准**：
- 配置的 Hook 能在对应事件触发时收到回调 / 命令被执行
- Hook 动作耗时超过超时上限被中断并记录
- Hook 抛错、URL 不可达、命令非 0 退出码均不影响对话进行
- 多次触发事件负载中的 trace_id / session_id 与执行一致

### 4.3 触发日志

**功能描述**：记录每次 Hook 执行的结果，供排查与审计。

**日志字段**：hook_id、事件、作用域、trace_id / session_id / user_id / tenant_id / agent_id、动作类型、目标（URL 或命令）、状态（success / failed / timeout）、耗时、HTTP 状态码 / 退出码、错误信息、触发时间。

**查询能力**：按时间范围、事件、Hook、状态筛选；单条可查看请求负载与响应摘要（敏感字段脱敏后）。

**验收标准**：
- 每次触发必有一条日志（含成功与失败）
- 触发日志按租户隔离，全局 Hook 日志仅平台管理员可见
- 可筛选、可查看错误原因

### 4.4 测试触发

**功能描述**：管理端提供"测试"按钮，手动模拟一次事件触发指定 Hook，验证配置正确性。

**交互**：选择 Hook → 点击测试 → 可选编辑模拟负载 → 展示执行结果（HTTP 状态 / 命令输出 / 耗时）。

**验收标准**：
- 无需真实对话即可验证 Hook 配置
- 测试结果（成功/失败/超时）明确展示

### 4.5 管理界面

**功能描述**：独立页面管理 Hook 与查看日志。

**菜单入口**：侧边栏新增"Hook 配置"菜单（位于"可观测性"下方，图标建议 `ApiOutlined`），页面结构：

- **Hook 列表页**：Hook 卡片/表格（名称、事件、作用域、动作类型、启用状态、最近触发时间、操作）。作用域按当前用户身份过滤可见范围。
- **创建/编辑表单**：按事件与动作类型动态渲染字段；事件下拉展示事件字典（名称 + 说明 + 负载字段）。
- **触发日志页**：日志表格 + 筛选 + 详情抽屉。
- **事件字典**：只读页面/弹窗展示全部事件定义与负载字段说明。

**验收标准**：
- 菜单入口在 Web 端可见，无权限用户看不到对应作用域的 Hook
- 创建表单字段随事件/动作类型联动
- 列表展示最近触发状态，异常 Hook 可快速定位

## 五、数据模型（草案）

沿用现有 `db/models.py` 风格：无外键约束、应用层维护归属关系，资源级表含 `tenant_id`、`created_by`、`visibility`。

### hooks（Hook 配置）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | uuid | 主键 |
| tenant_id / created_by | uuid | 归属（global 作用域 tenant_id 可为 null） |
| name | string(128) | 名称 |
| description | text | 描述 |
| scope | string | global / tenant / agent |
| agent_id | uuid? | scope=agent 时必填 |
| event | string(64) | 事件名 |
| action_type | string(16) | webhook / sandbox_command |
| config | jsonb | 动作参数（见下） |
| timeout_ms | int | 单次动作超时（默认 5000，≤30000） |
| retry_count | int | 失败重试次数（默认 1，≤3） |
| is_enabled | bool | 是否启用 |
| visibility | string | tenant/private（仅 tenant/agent 作用域） |
| created_at / updated_at | timestamptz | 时间戳 |

**config（jsonb）**：
- webhook：`{ "url": str, "headers": object, "secret": str?, "sign": bool }`
- sandbox_command：`{ "command": str, "workdir": str? }`

### hook_executions（触发日志）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | uuid | 主键 |
| hook_id | uuid | 关联 Hook |
| event / scope | string | 冗余，便于筛选 |
| trace_id / session_id / user_id / tenant_id / agent_id | uuid | 执行上下文 |
| action_type | string | webhook / sandbox_command |
| target | string(512) | URL 或命令（命令含脱敏占位） |
| status | string | success / failed / timeout / skipped |
| duration_ms | int | 耗时 |
| http_status / exit_code | int? | 结果细节 |
| error | text | 错误信息 |
| request_payload / response_preview | jsonb/text | 请求负载与响应摘要（敏感字段脱敏） |
| created_at | timestamptz | 触发时间 |

> 日志量可能较大（高频事件如 PreToolUse / PostToolUse 每工具一次）。默认**只记录 post 类事件与 Notification**，`PreToolUse`/`PreCompact` 是否落库可配置（`HOOK_LOG_PRE_EVENTS` 开关，默认关），避免日志爆炸。

## 六、技术方案要点

### 6.1 模块结构

新增 `backend/src/aio_agent_platform/hooks/`：

```
hooks/
├── __init__.py
├── events.py       # 事件注册表（事件名、描述、负载字段）
├── manager.py      # HookManager：加载、匹配、fire()
├── dispatcher.py   # 动作执行：webhook / sandbox_command 分发
├── signing.py      # HMAC-SHA256 签名
└── masking.py      # 敏感字段脱敏（password/token/api_key/secret）
```

### 6.2 生命周期挂载

在 `interface/api.py` 的 `lifespan` 中初始化 `HookManager` 挂到 `app.state`，与观测（observation）同层。事件埋点以**轻量调用**形式插入 `core/agent.py` 与 `tools/executor.py`：

- `AgentLoop.run()`：SessionStart（入口）、SessionEnd（三处：正常返回 / 超迭代 / `finalize_trace_error`）、PreCompact / PostCompact（压缩处）、Notification（上下文 >90% 告警）
- `_execute_tool_traced` / `ToolExecutor.execute`：PreToolUse（执行前）、PostToolUse（执行后）
- 委派子 Agent 复用同一套 Hook（trace 上下文已携带 agent_id）

> 埋点原则：只读 ObsContext + 调用 `hook_manager.fire()`，不引入额外查询；fire 内部异步，避免在 Agent 热路径同步执行动作。

### 6.3 动作执行

- **webhook**：`httpx.AsyncClient` POST JSON，支持自定义 Headers；签名开启时用 secret 对 body 做 HMAC-SHA256，放入 `X-Hook-Signature` 头；超时用 `timeout_ms` 控制，失败按 `retry_count` 重试（指数退避）。
- **sandbox_command**：复用 `SandboxManager.get_or_create` + `execute`，事件 JSON 经 stdin 传入（命令模板可含 `{{session_id}}` 等占位符，解析后通过 base64 安全传参，防注入）。

### 6.4 异步与递归防护

- `fire()` 将动作调度到后台 asyncio 任务（`asyncio.create_task` 或进程内队列 + worker），立即返回；日志异步写库。
- 执行上下文通过 `contextvars` 注入 `hook_triggered=True` 标志，`AgentLoop.run()` 检测到该标志时跳过 Hook 触发，阻断递归。
- 并发控制：同事件大量触发时按进程内信号量限制并发动作数（默认 16），防止风暴。

### 6.5 安全设计

| 风险 | 对策 |
|---|---|
| SSRF（webhook 指向内网） | URL 校验：禁止环回地址/保留地址/内网网段（可配置平台级 URL 域名白名单） |
| 请求伪造 | HMAC-SHA256 签名，secret 存库；签名密钥可对响应方展示仅供核对 |
| 敏感数据泄露 | 负载统一走 `masking.py`：对 arguments / headers 中 `password`、`token`、`api_key`、`secret` 等键打码；日志中命令不打印含密钥的占位符展开值 |
| 命令注入/逃逸 | 命令在沙箱容器内执行，受沙箱网络与权限限制；参数经 base64 传入避免 shell 拼接 |
| 越权 | 作用域 + tenant_id + visibility 应用层过滤；全局 Hook 接口仅管理员 |

## 七、非功能需求

### 7.1 性能

- Hook 埋点对 Agent 主循环的额外开销 < 5ms / 事件（不包含动作本身耗时）
- 单 Hook 动作超时上限 30s；动作并发上限可配置（默认 16）
- 触发日志高频事件默认关闭落库，防止表膨胀

### 7.2 可用性

- Hook 执行失败、超时、配置错误**不影响对话**，全部静默降级
- 动作依赖的外部服务不可用时，Hook 所在事件照常

### 7.3 可观测性

- 触发日志独立于对话，可筛选、可看错误详情
- Hook 执行耗时/成功率纳入既有观测体系（`record_tool_call` 风格），可后续接入可观测页

### 7.4 可扩展性

- 事件注册表集中声明，新增事件只需在 `events.py` 注册 + 对应埋点
- 动作类型可扩展（后续加 `mq`、`kafka` 等），dispatcher 按类型分发

## 九、验收标准汇总

1. 可创建/编辑/启停/删除 Hook，作用域与租户隔离生效。
2. 配置的 Hook 在对应事件触发时收到回调或命令被执行；同事件多 Hook 合并触发。
3. webhook 动作支持自定义 Headers 与 HMAC 签名；sandbox 命令在沙箱内执行并可读取事件 JSON。
4. Hook 超时/失败/抛错不影响对话，递归触发被阻断。
5. 触发日志完整、可筛选、可查看错误；敏感字段脱敏。
6. 测试触发无需真实对话即可验证配置。
7. SSRF 防护、签名校验、越权拦截生效。
8. Hook 埋点对 Agent 主流程无明显性能影响。

## 十一、术语表

| 术语 | 说明 |
|---|---|
| Hook | 绑定到生命周期事件的自动化动作配置 |
| 事件（Event） | Agent 执行过程中的一个节点（SessionStart / PostToolUse 等） |
| 动作（Action） | 触发后执行的动作：webhook 或 sandbox_command |
| 作用域（Scope） | Hook 生效范围：全局 / 租户 / Agent |
| 触发日志 | 每次 Hook 执行的记录，用于排查与审计 |
