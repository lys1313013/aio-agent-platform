# 宠物系统需求文档

> 日期：2026-08-02
> 目的：参考 OpenAI Codex Pets（2026-05 上线）为平台增加桌宠/陪伴宠物系统，将 Agent 运行状态可视化，提供情绪价值与轻度养成玩法。**硬性要求：宠物资源包直接兼容 Codex 宠物文件格式**，社区已有宠物（petdex 生态）可零改造导入使用。

## 1. 背景与目标

Codex Pets 的核心价值不是"养宠物"，而是**给 Agent 装上"在场感"**：宠物作为一个常驻悬浮窗，把 Agent 的运行状态（忙/闲/完成/出错）以动画形式表达出来，用户切走页面也能感知任务进度。本平台是 Web 应用，没有桌面客户端，宠物载体改为**Web 端全局悬浮组件**。

目标：

- 宠物常驻聊天页（可全局开启），动画状态与 Agent SSE 事件实时联动。
- 兼容 Codex 宠物包格式（`pet.json` 清单 + 精灵图），支持导入 petdex 社区宠物。
- **用户可自助上传宠物包，默认仅自己可见**；可见性按租户隔离可调（仅自己 / 本租户 / 全平台公开），管理员可上架官方宠物包。
- 轻度养成：使用平台积累经验、升级，解锁新形态（不做重度数值，不消耗 token）。
- 纯前端渲染 + 确定性状态机，**宠物本身不调用 LLM，零 token 消耗**。

## 2. 参考对象分析（Codex Pets）

| 维度 | Codex Pets | 本平台对应方案 |
|---|---|---|
| 载体 | 桌面 App 悬浮窗（类灵动岛） | Web 页面右下角悬浮组件，全局可拖拽 |
| 唤醒/收起 | `/pet` 命令、Cmd+K | `/pet` 斜杠命令 + 侧边栏开关 + 悬浮球本身 |
| 内置宠物 | 8 款 | 首期内置 4 款，其余走导入 |
| 自定义宠物 | `/hatch` AI 生成 / `npx petdex install` / 放 `~/.codex/pets/` 目录 | 用户自助上传宠物包（zip），格式与 Codex 一致；管理员另可发布官方包 |
| 状态联动 | 运行中忙碌、等待输入待机、完成庆祝 | 复用 SSE 事件流：reasoning/tool_call → 工作态，等待输入 → 待机，任务完成 → 庆祝，出错 → 沮丧 |
| 能力边界 | 纯陪伴，不能执行代码或聊天 | 同样纯展示，不进 Agent 工具循环 |
| 养成 | 无（仅外观收集） | 增加经验值/等级（与用量挂钩，差异化点） |

## 3. 角色与范围

| 角色 | 能力 |
|---|---|
| 普通用户 | 开启/关闭宠物、选择已激活宠物、互动、查看养成进度、**上传自己的宠物包并设置可见性（默认私有，可随时改成仅自己可见 / 租户内 / 公开）**、从宠物市场领养可见的宠物 |
| 管理员 | 拥有普通用户全部能力，另可：发布官方宠物包、强制下架任何公开/租户内宠物包、查看全平台宠物使用数据 |

可见性模型（四档，创建人可随时调整，**包括随时改回只有自己可见**）：

| 可见性 | 谁能看到 / 领养 | 谁能设置 |
|---|---|---|
| `private`（私有，默认） | 仅创建人本人 | 创建人 |
| `tenant`（租户内） | 与包同租户的全部用户（出现在其市场） | 创建人 |
| `public`（公开） | 全平台所有租户用户 | 创建人；管理员可强制下架 |
| `official`（官方） | 全平台用户（市场置顶标识） | 仅管理员 |

隔离规则：

- 包归属一个租户（`tenant_id`，上传时取创建人的当前租户），`tenant` 可见性即"该包 `tenant_id` 下的用户可见"。
- 创建人改可见性即时生效；从 `tenant`/`public` 收回为 `private` 后，**已领养的其他用户保留宠物与养成数据**，仅新用户不可再领养、不再出现在任何市场列表。
- 跨租户绝对隔离：A 租户用户对市场、搜索、包 ID 直查、资源 URL 均无法触达 B 租户的 `private`/`tenant` 包（接口返回 404，不暴露存在性）。
- 用户属于多个租户（`tenant_memberships`）时，市场展示"当前激活租户"可见的包；上传的包归属上传时的激活租户，不随用户切换租户而漂移。

不在本期范围：宠物对话（LLM 驱动）、宠物间社交、移动端 App、飞书渠道宠物。

## 4. 功能需求

### 4.1 宠物悬浮组件（核心）

- 聊天页右下角常驻悬浮宠物，可拖拽换位，位置记忆（localStorage）。
- 位置锚定：不记绝对像素，而记「距最近两条边的距离」（如：右边 24px + 底边 24px）。窗口缩放、外接显示器拔除后宠物保持对同一边角的相对距离，来回拉伸窗口位置可还原；窗口缩得过小时自动贴边，绝不渲染到视口外。收起/展开导致尺寸变化时同样按边距重算。旧版绝对像素格式的本地数据在加载时自动换算为锚定坐标。
- 全局开关：用户设置里"显示宠物"关闭后所有页面不渲染。
- 收起态：缩为一个 32px 小球，点击展开。
- 动画渲染：Canvas 或 CSS sprite 播放精灵图帧动画，帧率按宠物包清单定义；页面不可见时暂停渲染（`document.visibilitychange`）。

### 4.2 状态联动（状态机）

宠物状态由当前会话的 Agent 运行状态驱动，映射规则：

| Agent 状态（来源） | 宠物动画 | 说明 |
|---|---|---|
| 无会话 / 会话空闲 | `idle` | 眨眼、呼吸、随机小动作 |
| LLM streaming 中（`reasoning:` / `text_delta:`） | `think` | 思考动画 |
| 工具执行中（`tool_call:` 发出未返回） | `work` | 工作/忙碌动画 |
| 等待用户确认（AskUserQuestion 卡片挂起） | `wait` | 指向屏幕/期待动画 |
| 任务完成（AgentLoop 结束，无 tool_calls） | `celebrate` | 播放一次庆祝动画后回 idle |
| 执行出错 / 用户 `/stop` | `sad` | 沮丧动画，5 秒后回 idle |
| 用户 30 分钟无交互 | `sleep` | 睡觉动画 |

并发会话时以"最近活跃的会话"为准。状态机在前端 `chatStore` 派生，不改后端 SSE 协议。

### 4.3 互动

- 点击宠物：播放 `happy` 动画 + 随机气泡文案（本地文案库，不走 LLM）。
- 拖拽甩动：松手播放 `dizzy` 动画（彩蛋）。
- 右键/长按：快捷菜单（收起、换宠物、查看等级、去设置）。

### 4.4 养成系统（轻度）

| 行为 | 经验值 |
|---|---|
| 完成一次 Agent 任务（无中断跑完） | +10 |
| 一次任务中每成功调用一个工具 | +2（单次任务上限 +10） |
| 每日首次对话 | +20（签到性质） |
| 点击互动 | +1（每日上限 +5，防刷） |

- 等级公式：`level n` 需 `100 * n^1.5` 累计经验，上限 50 级。
- 等级奖励：特定等级解锁宠物新形态/配饰（如 Lv.10 换皮肤、Lv.20 特效光环），由宠物包内 `evolutions` 字段声明。
- 经验结算在后端进行（防篡改），复用 Agent 执行完成钩子写入；前端只读展示。
-  hover 宠物显示：等级、经验进度条、今日已获经验。

### 4.5 宠物管理与市场

- 新增"宠物"设置页（路由 `/settings/pets` 或独立 `/pets`），分三个区块：
  - 我的宠物：已领养/已上传的宠物列表，缩略图、等级、当前激活标记、启用/禁用开关。
  - 我的上传：自己上传的宠物包，显示可见性标识（私有/租户内/公开），可修改可见性、删除（见 4.6）。
  - 宠物市场：当前用户可见的全部宠物包（`official` + `public` + 本租户 `tenant` 包，official 置顶带标识），卡片式展示（预览动画直接播放精灵图），点击"领养"后即可激活。
- 每个用户同时只激活 1 只宠物；切换即时生效。

### 4.6 宠物包上传与权限

- **用户上传**：宠物页提供"上传宠物包"入口（zip），上传后默认为 `private` 且归属创建人当前租户。
- **可见性调整**：创建人可在 私有 / 租户内 / 公开 间随时切换（含随时改回仅自己可见）；管理员另可设 `official`。收窄可见性（公开→租户内→私有）后：
  - 已领养该包的其他用户**保留已领养宠物**（等级经验不丢），但不可见范围内的新用户无法再领养；
  - 创建人删除包时同理：已领养的用户保留使用权，仅包本身从所有市场消失。
- **管理员**：可上传官方包（`official`）、强制下架任何公开/租户内包（下架 = 转回私有效果）、删除违规包。
- 上传时后端统一校验（用户与管理员同一链路）：解压 → 校验 `pet.json` schema → 校验精灵图尺寸与清单声明一致 → 资源转存对象存储（MinIO，按 `pets/{tenant_id}/{owner_id}/{package_id}/` 前缀隔离存放）→ 写库。
- 校验失败给出具体错误（缺字段 / 帧尺寸不符 / 图片过大），不静默降级。
- **行映射**：上传对话框展示精灵图每行预览（播放动画），用户把各行拖给平台状态（idle 必选，其余可留空降级）；默认 row0=idle。映射存 `row_mapping`，不改原 pet.json。
- 配额限制：普通用户最多上传 20 个包，单包解压后 ≤ 10MB，防对象存储被刷。

## 5. Codex 宠物包格式兼容（硬性需求）

### 5.1 兼容目标

**从 petdex 生态下载的宠物包（zip 或目录）可不经修改直接导入本平台运行。** 用户的 Codex 本地宠物目录 `~/.codex/pets/<pet>/` 打包上传即可用。

### 5.2 包结构（已用真实包校准，2026-08-02）

> 以下格式基于对本机 `~/.codex/pets/` 下 5 个真实宠物包（doraemon / iikun / kun-like / noir-webling / vv）的逆向分析，**以此为准**。

```
<pet-name>/
├── pet.json            # 清单（必需，极简）
└── spritesheet.webp    # 精灵图（必需，文件名由清单指定）
```

真实 `pet.json` 全部字段（无任何动画/帧元数据）：

```json
{
  "id": "doraemon",
  "displayName": "Doraemon",
  "description": "A compact blue robot-cat Codex pet ...",
  "spritesheetPath": "spritesheet.webp",
  "spriteVersionNumber": 2,   // 可选，精灵图版本号
  "kind": "object"            // 可选，缺省为角色型宠物
}
```

精灵图约定（实测）：

- **RGBA WebP**，透明背景（非绿幕——图中绿色是生成残留，alpha 通道才是真背景）。
- **规则网格均分**：实测包均为 **192×208 px/帧、8 列**；行数不等（doraemon 9 行 72 帧，vv 11 行 88 帧）。上传时不硬编码帧尺寸，按"整除检测"推断：宽能被 8 整除且高能被行数整除，取 `192×208` 为首选假设，失败则尝试其他均分并让用户在上传预览中确认。
- **每行 = 一个动画，列 = 帧序列**（行间帧数可不满，尾部空帧 alpha 全 0，播放时跳过）。
- **Codex 有标准 9 行索引语义（2026-08-02 用 4 个本地官方包 + spec 校准）**：`pet.json` 确实不含动画字段，但 Codex 通过**固定的 9 行精灵图布局**隐含行序语义，行帧数实测 `[6,8,8,4,5,8,6,6,6]` 与官方约定逐行吻合：

  | 行 | 动画 | 帧数 | 平台状态 |
  |---|---|---|---|
  | 0 | idle 待机 | 6 | `idle` |
  | 1 | running-right | 8 | — |
  | 2 | running-left | 8 | — |
  | 3 | waving 挥手 | 4 | `happy` |
  | 4 | jumping 跳跃 | 5 | `celebrate` |
  | 5 | failed 失败 | 8 | `sad` |
  | 6 | waiting 等待 | 6 | `wait` |
  | 7 | running 工作中 | 6 | `work` |
  | 8 | review 思考 | 6 | `think` |

  `sleep` 无对应行 → 降级 `idle`。

- **自动映射**：≥9 行的包上传时按上表自动生成完整 `row_mapping`（存入平台侧字段，不改动原 pet.json），**无需手动配置**；用户显式传入的映射覆盖默认值，仍可在上传后通过弹窗调整。不足 9 行的自定义包不猜测，仅保证 `row0=idle`，其余需手动指定。

### 5.3 完整映射链路（单一权威参考）

三层映射串起来：**Agent 运行事件 → 平台状态 → Codex 精灵图行**。标准 9 行包全部自动映射；未映射的状态在运行时降级 `idle`。

| 平台状态 | 触发（Agent 事件） | Codex 行 | 行动画 | 帧数 | 默认自动映射 |
|---|---|---|---|---|---|
| `idle` | 会话空闲 / 默认 | 0 | idle 待机 | 6 | ✅ |
| `think` | LLM streaming（`reasoning:` / `text_delta:`） | 8 | review 思考 | 6 | ✅ |
| `work` | 工具执行中（`tool_call:` 未返回） | 7 | running 工作中 | 6 | ✅ |
| `wait` | AskUserQuestion 卡片挂起 | 6 | waiting 等待 | 6 | ✅ |
| `celebrate` | 任务完成（AgentLoop 正常结束） | 4 | jumping 跳跃 | 5 | ✅ |
| `sad` | 执行出错 / `/stop` | 5 | failed 失败 | 8 | ✅ |
| `happy` | 用户互动（点击/右键动作） | 3 | waving 挥手 | 4 | ✅ |
| `sleep` | 30 分钟无交互 | — | 无对应行 | — | ❌ → 降级 `idle` |
| — | running-right / running-left | 1 / 2 | 左右移动 | 8 | 平台未使用（保留给桌面端） |

**互动播放**（右键菜单「播放动画」/ 左键点击）：**直接按精灵图行操作**，不走 `row_mapping`。菜单列出精灵图的每一行，行名优先取动画映射里该行对应的状态名（待机/开心/工作…），否则取 Codex 标准行名（挥手/跳跃/思考…），都没有则显示「动画 N」。点击任一行即播放该行动画，并触发 interact +1 经验（每日上限 5）。

> 映射存于 `pet_packages.row_mapping`（JSONB，平台侧字段），不改动原 `pet.json`。运行时 `resolveRow(state) = row_mapping[state] ?? row_mapping.idle ?? 0`；互动播放行由前端直接指定 `row`，不经此函数。

### 5.4 兼容规则

1. **原包零修改**：上传的 zip/目录原样保存，pet.json 原文存入 manifest JSONB；平台附加数据（行映射、可见性）存平台字段，保证包可双向流通（导出回 Codex 逐字节一致）。
2. **未知字段原样保留**：`kind`、`spriteVersionNumber` 及未来新增字段不丢弃。
3. **状态动画缺失降级**：必需映射只有 `idle`；`think/work/wait/celebrate/sad/sleep/happy` 未映射的行一律降级为 `idle`（celebrate 降级时加速播放一遍再回 idle）。
4. **资源限制**：单张精灵图 ≤ 4096×4096、解压后单包 ≤ 10MB、帧数 ≤ 512，超限拒绝上传（防恶意大图撑爆浏览器内存）。
5. **Codex 特有行为不实现**：依赖桌面端的能力（窗口跟随、多屏游走）忽略，仅保证动画正确渲染。
6. **导出**：平台内上传的包支持重新下载，下载产物与原包逐字节一致。

## 6. 后端设计

### 6.1 数据表

| 表 | 关键字段 | 说明 |
|---|---|---|
| `pet_packages` | id, name, display_name, description, owner_id(创建人), tenant_id(归属租户), visibility(private/tenant/public/official), manifest(JSONB 原始 pet.json 原文), row_mapping(JSONB 平台侧 行→状态 映射 {idle:0, work:1, ...}), frame_width, frame_height, row_count, asset_prefix(对象存储路径 `pets/{tenant_id}/{owner_id}/{package_id}/`), status(正常/被下架), created_at | 宠物包目录，用户包与官方包同表 |
| `user_pets` | id, user_id, package_id, level, exp, is_active, adopted_at | 用户领养的宠物（领养即 insert，激活即 is_active=true，同一用户至多一条 is_active） |
| `pet_exp_logs` | id, user_id, pet_id, delta, reason(task_complete/tool_call/daily_first/interact), ref_id, created_at | 经验流水，用于审计和防刷判定 |

可见性在应用层判定：`pet_packages` 查询条件为 `visibility IN ('public','official') OR (visibility = 'tenant' AND tenant_id = 当前用户租户) OR owner_id = current_user`；`official` 包仅管理员可写。RLS 增加 `app.current_tenant_id`（与现有 `app.current_user_id` 并列设置）：`pet_packages` 策略为 `visibility IN ('public','official') OR tenant_id = current_tenant OR owner_id = current_user`，`user_pets` / `pet_exp_logs` 按 `user_id` 隔离。对象存储按 `pets/{tenant_id}/` 前缀隔离，非公开包资源 URL 需签名且仅可见范围内用户可签发。

### 6.2 接口

| 接口 | 说明 |
|---|---|
| `GET /api/pets/market` | 宠物市场列表（`official` + `public` + 本租户 `tenant` 包；含预览图 URL、manifest 中动画定义） |
| `POST /api/pets/packages` | **用户上传宠物包** zip（multipart），校验、存 MinIO、写库，visibility 默认 `private`，tenant_id 取当前租户 |
| `GET /api/pets/packages/mine` | 我上传的宠物包列表 |
| `PUT /api/pets/packages/{id}/visibility` | 修改可见性（private / tenant / public，仅创建人；official 仅管理员可设） |
| `PUT /api/pets/packages/{id}/row-mapping` | 修改 状态→行 动画映射（上传后/后续调整，仅创建人） |
| `DELETE /api/pets/packages/{id}` | 删除自己上传的包（已领养的用户保留宠物，仅市场不可见） |
| `POST /api/pets/{package_id}/adopt` | 领养（insert user_pets；校验包对自己在可见范围内；已领养幂等返回） |
| `POST /api/pets/{user_pet_id}/activate` | 激活（事务内先清该用户其他 is_active） |
| `GET /api/pets/mine` | 我的宠物列表（含等级、经验、今日经验） |
| `POST /api/pets/{user_pet_id}/interact` | 点击互动上报（+1 exp，服务端校验每日上限） |
| `GET /api/pets/active` | 当前激活宠物完整信息（前端悬浮组件初始化用，含 manifest 和精灵图签名 URL） |
| `POST /api/admin/pet-packages` | 管理员上传官方包（visibility=`official`），复用用户上传同一校验链路 |
| `PUT /api/admin/pet-packages/{id}/takedown` | 管理员强制下架公开包（转私有效果）/ 恢复 |

### 6.3 经验结算钩子

在 `AgentLoop.run()` 正常结束的收尾处（token_usage_daily 写入的同一位置）触发 `pet_service.award_task_exp(user_id, session_id, tool_call_count)`：

- 判定"完成"= Agent 自然结束（非 `/stop`、非异常）。
- 内部写 `user_pets.exp` + `pet_exp_logs`，失败仅记日志不影响主流程（宠物是附属系统，绝不能拖垮对话链路）。
- 每日首次对话 +20 通过 `pet_exp_logs` 当日去重判定。

## 7. 前端设计

### 7.1 组件结构

- `components/pet/PetWidget.tsx` — 全局悬浮组件，挂在 App 根布局（登录后渲染）。
- `components/pet/PetCanvas.tsx` — 精灵图渲染器：按 manifest 切帧、按 frameRate 播放、支持 loop/once 与完成回调（celebrate 播完回 idle）。
- `components/pet/petStateMachine.ts` — 状态机，输入为 `chatStore` 的 SSE 事件派生状态，输出动画名；处理降级规则（缺动画 → idle）。
- `pages/PetsPage.tsx` — 宠物管理/市场页。
- 管理后台 `pages/admin/PetPackagesPage.tsx` — 上传与上下架。

### 7.2 状态来源

复用 `stores/chatStore.ts` 现有 SSE 事件，新增派生 selector `petMood`：

```
streaming && hasToolCallPending → work
streaming                       → think
pendingConfirmation             → wait
idle && lastRunOk               → celebrate(once) → idle
idle && lastRunFailed           → sad(5s) → idle
lastActivity > 30min            → sleep
```

### 7.3 资源加载

- 精灵图经后端签名 URL 加载，浏览器缓存（内容 hash 进 URL）。
- 激活宠物的 manifest 在登录后随 `GET /api/pets/active` 一次拉取，zustand 缓存。

## 8. 非功能需求

- **零 token**：宠物所有行为不经过 LLM，气泡文案为本地静态文案库。
- **性能**：悬浮组件空闲时 CPU 占用可忽略（requestAnimationFrame + 页面不可见暂停）；精灵图懒加载，未激活宠物不下载。
- **隔离**：经验写入失败、宠物接口 5xx 均不影响聊天主流程，前端组件崩溃不带出白屏（ErrorBoundary 局部降级为不显示宠物）。
- **安全**：上传 zip 服务端解压校验（防 zip slip、限制总大小 10MB、限制文件数）；图片仅允许 png/webp/gif。
- **多租户与权限**：宠物包按租户 + 创建人双重维度隔离——`private` 仅创建人可见，`tenant` 仅同租户可见，跨租户用户对市场、搜索、直接访问包 ID / 资源 URL 均不可触达（接口返回 404 而非 403，不暴露存在性）；RLS 使用 `app.current_tenant_id` + `app.current_user_id` 双重上下文；`user_pets` / `pet_exp_logs` 按 `user_id` 隔离。

## 10. 验收标准

1. 从 petdex 下载的宠物包 zip 上传后无需修改即可预览并被激活使用。
2. 用户上传的包默认私有：其他用户（含同租户）在市场看不到、按包 ID 访问接口返回 404、资源签名 URL 无法签发。
3. 创建人将包改为「租户内可见」后，同租户用户可领养，其他租户用户仍不可见；改为「公开」后全平台可领养。
4. 创建人随时可将包改回「只有自己可见」：此后新用户（含同租户）不可再领养、市场不再展示，已领养用户数据与使用权不受影响。
5. Agent 执行任务全过程中，宠物动画按 4.2 映射表正确切换，任务结束播放庆祝动画。
6. 宠物接口全部不可用（断网/500）时，聊天功能无任何影响。
7. 完成一次任务后经验与等级按 4.4 规则正确累计，刷新页面数据不丢。
