## 1. 宠物系统基础设计（对应 01 需求）

### 1.1 数据表

| 表 | 关键字段 | 说明 |
|---|---|---|
| `pet_packages` | id, name, display_name, description, owner_id(创建人), tenant_id(归属租户), visibility(private/tenant/public/official), manifest(JSONB 原始 pet.json 原文), row_mapping(JSONB 平台侧 行→状态 映射 {idle:0, work:1, ...}), frame_width, frame_height, row_count, asset_prefix(对象存储路径 `pets/{tenant_id}/{owner_id}/{package_id}/`), status(正常/被下架), created_at | 宠物包目录，用户包与官方包同表 |
| `user_pets` | id, user_id, package_id, is_active, adopted_at | 用户领养的宠物（领养即 insert，激活即 is_active=true，同一用户至多一条 is_active） |
| `pet_exp_logs` | id, user_id, pet_id, delta, reason(bubble_llm), ref_id, created_at | 行为计数表，当前用于智能气泡每日配额计数 |

可见性在应用层判定：`pet_packages` 查询条件为 `visibility IN ('public','official') OR (visibility = 'tenant' AND tenant_id = 当前用户租户) OR owner_id = current_user`；`official` 包仅管理员可写。RLS 增加 `app.current_tenant_id`（与现有 `app.current_user_id` 并列设置）：`pet_packages` 策略为 `visibility IN ('public','official') OR tenant_id = current_tenant OR owner_id = current_user`，`user_pets` / `pet_exp_logs` 按 `user_id` 隔离。对象存储按 `pets/{tenant_id}/` 前缀隔离，非公开包资源 URL 需签名且仅可见范围内用户可签发。

### 1.2 接口

| 接口 | 说明 |
|---|---|
| `GET /api/pets/market` | 宠物市场列表（`official` + `public` + 本租户 `tenant` 包；含预览图 URL、manifest 中动画定义） |
| `POST /api/pets/packages` | **用户上传宠物包** zip（multipart），校验、存 MinIO、写库，visibility 默认 `private`，tenant_id 取当前租户 |
| `GET /api/pets/packages/mine` | 我上传的宠物包列表 |
| `PUT /api/pets/packages/{id}/visibility` | 修改可见性（private / tenant / public，仅创建人；official 仅管理员可设） |
| `PUT /api/pets/packages/{id}/row-mapping` | 修改 状态→行 动画映射（上传后/后续调整，仅创建人） |
| `DELETE /api/pets/packages/{id}` | 删除自己上传的包（已领养的用户保留宠物，仅市场不可见） |
| `POST /api/pets/{package_id}/adopt` | 领养（insert user_pets；校验包对自己在可见范围内；已领养幂等返回） |
| `POST /api/pets/{user_pet_id}/activate` | 激活（事务内先清该用户其他 is_active） |
| `GET /api/pets/mine` | 我的宠物列表 |
| `POST /api/pets/{user_pet_id}/interact` | 点击互动上报（仅归属校验并刷新实例数据，无经验奖励） |
| `GET /api/pets/active` | 当前激活宠物完整信息（前端悬浮组件初始化用，含 manifest 和精灵图签名 URL） |
| `POST /api/admin/pet-packages` | 管理员上传官方包（visibility=`official`），复用用户上传同一校验链路 |
| `PUT /api/admin/pet-packages/{id}/takedown` | 管理员强制下架公开包（转私有效果）/ 恢复 |

### 1.3 前端设计

#### 1.3.1 组件结构

- `components/pet/PetWidget.tsx` — 全局悬浮组件，挂在 App 根布局（登录后渲染）。
- `components/pet/PetCanvas.tsx` — 精灵图渲染器：按 manifest 切帧、按 frameRate 播放、支持 loop/once 与完成回调（celebrate 播完回 idle）。
- `components/pet/petStateMachine.ts` — 状态机，输入为 `chatStore` 的 SSE 事件派生状态，输出动画名；处理降级规则（缺动画 → idle）。
- `pages/PetsPage.tsx` — 宠物管理/市场页。
- 管理后台 `pages/admin/PetPackagesPage.tsx` — 上传与上下架。

#### 1.3.2 状态来源

复用 `stores/chatStore.ts` 现有 SSE 事件，新增派生 selector `petMood`：

```
streaming && hasToolCallPending → work
streaming                       → think
pendingConfirmation             → wait
idle && lastRunOk               → celebrate(once) → idle
idle && lastRunFailed           → sad(5s) → idle
lastActivity > 30min            → sleep
```

#### 1.3.3 资源加载

- 精灵图经后端签名 URL 加载，浏览器缓存（内容 hash 进 URL）。
- 激活宠物的 manifest 在登录后随 `GET /api/pets/active` 一次拉取，zustand 缓存。

## 2. 宠物绑定智能体设计（对应 02 需求）

### 2.1 数据表变更

| 表 | 变更 | 说明 |
|---|---|---|
| `pet_packages` | + `default_agent_id UUID NULL` | 包级默认人设 Agent |
| `user_pets` | + `agent_id UUID NULL` | 实例级绑定 |
| `conversations` | + `source VARCHAR(16) DEFAULT 'chat'`（取值 `chat` / `pet`） | 区分宠物闲聊会话；已有多渠道接入若已有等价字段则复用 |
| `token_usage_daily` | source 新增 `pet_bubble` / `pet_chat` | 成本归集 |

均无外键约束（沿用项目惯例，应用层维护关系 + 实时可见性校验）。

### 2.2 接口

| 接口 | 说明 |
|---|---|
| `PUT /api/pets/{user_pet_id}/agent` | 实例级绑定/解绑（body: `{agent_id: UUID \| null}`；校验 Agent 对当前用户可见） |
| `PUT /api/pets/packages/{id}/default-agent` | 包级默认人设（仅包创建人/管理员；校验 Agent 对创建人可见） |
| `POST /api/pets/{user_pet_id}/bubble` | 智能气泡（SSE 流式返回 `text_delta`；未绑定/超限/失败时回退响应 `{fallback: true, text: "..."}`，前端直接展示静态文案） |
| `POST /api/pets/{user_pet_id}/chat` | 开启/复用宠物闲聊会话，返回 `conversation_id`；之后走现有会话消息接口 + SSE |
| `GET /api/pets/active` | 响应扩展：`agent`（解析后的绑定 Agent 简要信息：id/name/icon + 生效层级 instance/package） |

### 2.3 执行链路

**气泡（bubble）**：不走 `AgentLoop`——单轮、无工具、无历史，直接调 LLM client（合成 prompt → stream → 逐字 yield）。独立轻量链路，避免 AgentLoop 的工具注册、上下文管理开销。写入 `token_usage_daily(source='pet_bubble')`。配额判定用 `pet_exp_logs` 同款当日计数（reason=`bubble_llm`，成功生成才记）。

**闲聊（chat）**：走标准 `AgentLoop`，但构造时注入约束：

- `enabled_tools` 过滤为白名单（记忆类），无视 Agent 原配置的工具列表；
- `max_iterations = min(agent.max_iterations, 3)`；
- system_prompt 按 2.3 合成（agent.system_prompt + 宠物人设包装）；

**可见性实时校验**：每次解析绑定 Agent 时检查（a) Agent 存在且 `is_active`；(b) 对当前用户可见（owner 或同租户 tenant 可见）。失败即降级，缓存当次请求内结果。

### 2.4 降级矩阵

| 场景 | 行为 |
|---|---|
| 未绑定任何 Agent | 本地静态文案（现状） |
| 绑定 Agent 被删除/改私有/停用 | 回退下一级 → 最终静态文案 |
| LLM 调用异常/超时 | 本次回退静态文案，记 warn 日志 |
| 气泡配额超限 | 回退静态文案，hover 提示"今日智能互动已达上限" |
| 全站关闭宠物智能互动 | 全部回退静态文案，绑定配置保留 |
| 宠物接口/LLM 全挂 | 聊天主流程零影响（沿用既有 ErrorBoundary + 附属系统隔离原则） |

### 2.5 前端设计

- `petStore`：新增 `boundAgent`（解析结果）与 `bubbleStreaming` 状态；气泡文本支持流式累积。
- `PetWidget`：
  - 气泡组件支持打字机效果（流式追加）；3s 无首个 token 直接切静态文案。
  - 右键菜单：「和 TA 聊聊」入口 + 当前人设展示。
  - 新增 `PetChatPanel.tsx`：宠物旁的浮动聊天窗（约 320×400px），复用消息气泡样式组件，位置跟随宠物（锚定逻辑复用 widget 的边距策略）。
- `PetsPage`：宠物卡片加"绑定智能体"选择器；包卡片加"默认人设"设置；闲聊/播报开关。
- 系统配置页：宠物智能互动总开关 + 每日气泡配额配置项。
- 会话列表：`source='pet'` 会话带宠物角标，点击正常进入会话（全屏继续聊）。
