# 大模型可观测性需求文档

> 日期：2026-08-06
> 目的：建立覆盖 **LLM 调用 → 工具执行 → Agent 执行链路 → 会话 → 用户/租户 → 质量** 的完整观测体系，回答"Token 花在哪、哪里慢、哪里出错"三类问题，为优化提示词、排查故障、配额管理提供数据支撑。
> 范围说明：本期不接入 Langfuse，不启用成本（cost_usd 维持 0）。技术实现见《02-技术方案.md》，前端展示设计见《03-前端展示设计.md》。

## 1. 背景与问题

当前平台对"大模型用量"的观测**只有 Token 总量一个粗略口径**，且分散、不完整，无法回答：

| 业务问题 | 现状 |
|---|---|
| Token 花在哪？哪些工具结果/历史消息/系统提示在烧 token？ | 只有总量，无拆解 |
| 每个工具调用耗时多少、失败率多高？ | 工具耗时已计算但**未落库、未聚合** |
| 一次对话平均耗时/平均 token 是多少？ | 无会话级聚合 |
| 每次 Agent 执行（Trace）内部发生了什么？ | 无结构化执行记录 |
| 缓存有没有生效、省了多少 token？ | 缓存 token 未采集 |
| LLM 调用失败/重试/超时率？ | 只打日志，无指标与告警 |
| 上下文是否快塞满了、压缩频繁不频繁？ | 无利用率与压缩监控 |

**目标**：自建"三路观测"体系——**明细表（记录每次 LLM 调用/工具调用/Agent 执行）＋ 预聚合表（报表秒查）＋ Prometheus 指标（实时告警）**，配套管理端观测页面。

## 2. 角色与权限

| 角色 | 可观测范围 | 入口 |
|---|---|---|
| 管理员 | 全平台：所有用户/租户/智能体/模型的 Trace、工具、质量 | 观测页 `/observability` |
| 普通用户 | 维持现状，仅个人用量 | 用量页 `/usage`（不变） |

## 3. 观测指标体系

按对象分层。**任何指标的维度统一携带**：`tenant_id / user_id / session_id / agent_id / model / trace_id / 时间戳`，保证任意下钻。指标的数据来源见技术方案《05 数据来源对照》。

### 3.1 LLM 调用层（每次模型请求）

| 指标 | 定义 | 用途 |
|---|---|---|
| `prompt_tokens` / `completion_tokens` / `total_tokens` | 输入/输出/合计 token | 用量基础 |
| `cache_read_tokens` | 命中缓存的输入 token | 评估缓存收益 |
| `cache_creation_tokens` | 写入缓存的 token | 评估缓存开销 |
| `cache_hit_rate` | cache_read / prompt_tokens | 缓存效率 |
| `context_window` / `context_utilization` | 模型上下文窗口 / 输入 token 占比 | 预警上下文将满 |
| `ttft_ms` | 首 token 延迟 | 感知响应速度 |
| `duration_ms` | 单次调用总耗时 | 延迟定位 |
| `output_tokens_per_sec` | 输出 token / 生成耗时 | 吞吐 |
| `retry_count` | 重试次数 | 稳定性 |
| `final_status` | 成功 / 失败 | 错误率 |
| `error_type` | 超时 / 连接错误 / 限流 / 5xx / 上下文超长 / 内容审核 | 错误归类 |
| `stop_reason` | stop / length / tool_calls / max_tokens | 是否被截断 |
| `temperature` / `max_tokens` / `tools_count` | 请求参数 | 归因 |
| `call_order` | 一次 Agent 执行中的第几轮 | 轮次分析 |
| `model` / `provider` | 模型标识 | 维度 |

### 3.2 工具执行层（每次工具调用）

| 指标 | 定义 | 用途 |
|---|---|---|
| `tool_name` | 工具名 | 维度 |
| `exec_type` | sandbox / direct / mcp / remote / builtin | 分类 |
| `duration_ms` | 工具执行耗时 | **工具耗时** |
| `is_error` / `error_type` | 成功/失败 + 错误类型 | **工具错误率** |
| `arg_bytes` / `arg_chars` | 参数大小 | 输入体量 |
| `output_bytes` / `output_chars` | 输出大小 | **注入上下文体量** |
| `est_injected_tokens` | 输出估算 token | 定位"工具烧 token" |
| `is_truncated` | 输出是否被截断 | 结果质量 |
| `is_concurrent` | 是否与委派等工具并发执行 | 时序分析 |
| `call_order` | 执行链路中的序号 | 归因 |
| `duplicate_ratio` | 同一 turn 内同工具重复调用占比 | 工具设计问题 |

### 3.3 Agent 执行链路层（Trace / 每次完整 Agent.run）

| 指标 | 定义 | 用途 |
|---|---|---|
| `status` | completed / interrupted / timeout / error | **对话成功率** |
| `iteration_count` | LLM 调用轮数 | 效率 |
| `tool_call_count` | 工具调用总数 | 复杂度 |
| `total_tokens` | 累计 token | 单次执行体量 |
| `duration_ms` | 端到端耗时 | **对话平均耗时** |
| `is_compressed` | 是否触发上下文压缩 | 压缩频率 |
| `tokens_before_compress` / `tokens_after_compress` / `saved_tokens` | 压缩前后与节省量 | **压缩收益** |
| `summary_tokens` | 摘要本身 token | 压缩开销 |
| `hit_max_iterations` | 是否顶到 max_iterations | 死循环/发散 |
| `llm_call_count_breakdown` | 纯文本轮 / 工具轮 / 确认轮分布 | 轮次构成 |

### 3.4 对话/会话层（聚合口径）

| 指标 | 定义 | 用途 |
|---|---|---|
| `session_total_tokens` | 会话累计 token | 会话体量 |
| `session_avg_duration_ms` | 会话平均耗时 | **对话平均耗时** |
| `session_avg_tokens` | 会话平均 token（含 per-message / per-turn） | **对话平均 token** |
| `avg_llm_calls_per_turn` | 每轮平均 LLM 调用 | 轮次效率 |
| `avg_tool_calls_per_turn` | 每轮平均工具调用 | 复杂度 |
| `first_token_latency_ms` | 用户发消息 → 首个 token 回流 | 首响体验 |
| `turn_interval_ms` | 相邻用户消息间隔 | 活跃度 |
| `multi_turn_ratio` | 多轮对话占比 | 会话粘性 |
| `token_growth_per_turn` | 每轮上下文增量 | 长上下文膨胀监控 |

### 3.5 用户/租户层

| 指标 | 定义 | 用途 |
|---|---|---|
| 日/月 token、请求数（按用户/租户） | 复用 `token_usage_daily` 扩展 | 报表 + 配额 |
| 活跃用户数 / 人均 token | 按日 | 平台规模 |
| 模型分布 / 智能体分布 / 渠道分布 | token 占比 | 资源优化 |
| 租户配额使用率 | 已用 / 配额（若启用配额） | 配额管理 |

### 3.6 质量与体验层

| 指标 | 定义 | 用途 |
|---|---|---|
| `llm_call_error_rate` | 失败调用 / 总调用 | **模型错误率** |
| `tool_error_rate` | 失败工具 / 总工具 | **工具错误率** |
| `retry_rate` | 发生过重试的调用占比 | 稳定性 |
| `invalid_tool_call_rate` | 模型产出但注册表无匹配的工具名 | 工具定义问题 |
| `empty_response_rate` | 无文本无工具调用的完成 | 模型行为异常 |
| `context_compress_rate` | 触发压缩的 trace 占比 | 上下文管理 |
| `interrupt_rate` | 用户中途停止占比 | 体验 |
| `tool_useless_rate`（进阶） | 工具结果为空/被后续忽略 | 工具质量 |

### 3.7 系统/渠道/后台任务层

| 指标 | 定义 | 用途 |
|---|---|---|
| 渠道（Web/飞书等）调用量、token、失败率、耗时 | 按渠道关联会话 | 渠道对比 |
| 定时任务（cron）执行次数、token、耗时、失败率 | 后台任务 | 后台消耗 |
| 委派（子 Agent）调用量、token、耗时、嵌套深度 | 委派记录 | 多智能体消耗 |
| 宠物闲聊 token 占比 | 会话来源维度 | 资源占用 |
| 记忆/技能/知识注入的 token 占比（进阶） | 拆分系统提示各块 token | 提示词优化 |

## 4. 功能需求

### 4.1 管理员观测页 `/observability`

独立路由，侧边栏入口（位于"用量统计"上方，图标 `LineChartOutlined`）。页面含五个子模块，子模块间用 Tab 切换，顶部为全局筛选栏。详细页面设计见《03-前端展示设计.md》。

**4.1.1 实时监控板（Overview）**

- 指标卡（6 张）：今日 LLM 调用数、LLM 失败率、工具错误率、平均 TTFT、延迟 P95、今日 token 消耗。
- 折线趋势（可按分钟/小时/天切换，自动刷新）：
  - LLM 调用量、LLM 失败率、**工具调用量、工具失败率**、延迟 P95、token 消耗速率、上下文利用率 P95。
- **工具维度独立成图**：工具调用量趋势、工具失败率趋势各自单独一张图（失败率带阈值线，超阈值时段高亮，可点击跳转对应 Trace 明细）。

**4.1.2 Trace 明细（Traces）**

- 分页表格，列：trace_id、时间、会话、智能体、模型、LLM 轮数、工具数、token、耗时、状态。
- 支持筛选：时间范围、状态、模型、智能体、会话。
- 行点击打开**详情下钻**（抽屉）：
  - 逐步还原执行链路：LLM 调用（token/耗时/TTFT/stop_reason）→ 工具调用（耗时/错误/输出大小/是否截断）→ 下一轮 LLM。
  - 展示压缩事件：压缩前/后 token、节省量。
  - 每条错误调用给出错误类型与可读描述。

**4.1.3 聚合报表（Stats）**

- 分布图（按模型 / 智能体 / 用户 / 租户 切换）：token、耗时、错误率三个口径。
- 时间范围切换：近 7 天 / 近 30 天 / 自定义。

**4.1.4 工具排行（Tools）**

- 表格 + 条形图双形态，按指标切换：平均耗时 / 错误率 / 调用次数 / 注入 token（`est_injected_tokens`）。
- 目标：一眼定位"哪个工具最慢 / 最容易错 / 最烧 token"。
- **单工具趋势下钻**：点击某工具行，展示该工具的独立时间序列趋势（调用量 + 失败率，分钟/小时/天切换），定位"这个工具何时变慢、何时开始高频出错"。

**4.1.5 对话质量（Quality）**

- 趋势：对话平均耗时、对话平均 token、每轮平均 LLM/工具调用数、多轮占比。
- 压缩监控：压缩触发率、压缩节省量趋势。
- 首响体验：首 token 延迟分布（P50/P95）。

### 4.2 数据导出

- 聚合报表、工具排行、Trace 明细支持 CSV 导出（复用现有导出能力，范围与当前筛选一致）。

### 4.3 告警需求

| 告警 | 条件 | 级别 | 接收渠道 |
|---|---|---|---|
| LLM 失败率突增 | 时间窗内失败率 > 5% 且较前一周期翻倍 | P1 | 企微/飞书 webhook + 日志 |
| 工具错误率超标 | 某工具错误率 > 20% | P2 | 同上 |
| 延迟劣化 | LLM 延迟 P95 > 阈值（默认 30s）持续 5 分钟 | P2 | 同上 |
| 上下文接近满 | 上下文利用率 P95 > 90% | P3 | 日志 |
| 压缩频繁 | 压缩触发率 > 30% | P3 | 同上 |
| 租户配额超限（若启用） | 使用率 > 80% | P2 | 通知租户 |

> 阈值可配置；告警触发后支持在观测页查看历史告警记录。

## 5. 非目标（本期不做）

- 实时秒级流式展示（先做分钟级自动刷新）
- 大模型输入输出内容的敏感审计（内容安全，另行立项）
- 多环境（dev/prod）对比
- 成本计算与成本告警
- Langfuse 接入与对接（后续可评估）

## 6. 分期规划

**MVP（第一期）— 数据底座 + 核心观测页**

1. 三张明细表 + 异步采集
2. `token_usage_daily` 扩展缓存 token 列
3. 预聚合表（工具日表、性能日表）
4. 观测页：实时监控板 + Trace 明细与下钻 + 聚合报表 + 工具排行

**第二期 — 对话质量与告警**

1. 对话质量模块（平均耗时/平均 token/压缩监控）
2. `/metrics` + Prometheus + 基础告警（失败率 / 延迟劣化）
3. CSV 导出

**第三期 — 智能与治理**

1. 告警规则可配置 + 告警历史
2. 租户配额（按 token 限额）与预警
3. 系统提示词分块 token 归因 → 提示词优化建议
4. 工具质量分析（无效调用 / 重复调用）→ 工具重构建议

## 7. 已确认决策

1. 观测体系 = 自建明细表（明细与精确聚合）＋ 预聚合表（报表）＋ Prometheus（实时告警），三路并行；**Langfuse 本期不接入**。
2. 成本不启用：`cost_usd` 维持 0（沿用 15-数据报表 决策），不引入模型价格。
3. 观测页独立路由 `/observability`，权限管理员；普通用户 `/usage` 不变。
4. 明细表永久保留。
5. 告警阈值默认值：失败率 5%、工具错误率 20%、延迟 P95 30s、利用率 90%、压缩率 30%、配额 80%。
