# 知识图谱知识库需求文档（PRD）

> 创建日期：2026-08-07
> 状态：待评审
> 版本：1.0

---

## 一、背景与目标

### 1.1 背景

当前系统的"知识库"是 RAGFlow 的薄封装：前端只录入 `dataset_id`，检索时通过 HTTP 调用外部 RAGFlow 服务，知识以扁平的向量分块形式存在外部系统里。存在以下问题：

- **无结构化建模**：知识没有实体（Entity）与关系（Relationship）的概念，无法回答"A 和 B 是什么关系""谁依赖谁"这类关系型问题。
- **无法多跳推理**：扁平分块只能做"相似度召回"，无法沿关系链推理（A 关联 B、B 关联 C，问 A 与 C）。
- **依赖外部服务**：知识与图谱完全寄存在 RAGFlow，外部服务不可用时知识全部不可用，且无法可视化、无法人工审核结构。
- **无法沉淀**：知识入库后不可编辑实体、关系，无法持续校准。

本模块的目标是在 **PostgreSQL 之上自建知识图谱知识库**，实现"真正的知识库"：文档入库 → LLM 抽取实体与关系 → 图结构存储 → 子图检索辅助 Agent 回答。

### 1.2 与 RAGFlow 知识库的关系

两种知识库定位互补，统一归入"知识库"菜单，互不替换：

| 维度 | 知识图谱知识库（本模块） | RAGFlow 知识库（现有） |
|---|---|---|
| 检索方式 | 结构化：实体链接 + 子图遍历 | 语义：向量相似度召回 |
| 回答类型 | "X 和 Y 是什么关系"、多跳推理 | "哪段文本提到 X" |
| 知识形态 | 实体-关系三元组 | 文档分块 |
| 数据存储 | PostgreSQL（自建） | RAGFlow 外部服务 |
| 可视化 | 图视图 + 人工复核 | 无 |

### 1.3 目标

- 支持创建、管理图谱知识库（租户级隔离）
- 支持文档入库与分块
- 支持 LLM 抽取实体与关系，形成知识图谱
- 支持图谱可视化与人工复核
- 支持子图检索，为 Agent 提供结构化上下文
- 支持 Agent 绑定图谱知识库，对话中自动检索

## 二、用户角色

| 角色 | 权限 | 说明 |
|------|------|------|
| 管理员 | 创建/管理图谱知识库、上传文档、触发抽取、复核实体关系、绑定 Agent | 知识图谱的维护者 |
| 普通用户 | 与绑定图谱知识库的 Agent 对话 | 消费图谱知识 |

权限沿用现有模型：资源按 `tenant_id`（租户级）+ `visibility`（tenant/private）+ `created_by`（创建者）做应用层隔离，不引入新的权限体系。

## 三、功能需求

### 3.1 图谱知识库管理

**功能描述**：管理员可创建、编辑、删除、启用/禁用图谱知识库。

**知识库属性**：
- **名称**：显示名称
- **描述**：内容描述（帮助系统判断何时使用该知识库）
- **启用状态**：是否参与检索
- **可见范围**：tenant（租户内可见）/ private（仅创建者）

**验收标准**：
- 可创建/编辑/删除图谱知识库，删除前二次确认
- 可启用/禁用（禁用的知识库不参与 Agent 检索）
- 可见范围与现有知识库一致，仅创建者可修改
- 删除知识库时级联清理其文档、实体、关系，并解除 Agent 绑定

### 3.2 文档入库与分块

**功能描述**：向图谱知识库上传文档（粘贴文本 / 上传文件），系统按规则分块，作为 LLM 抽取的输入。

**支持输入**：
- 直接粘贴文本（Markdown/纯文本）
- 上传文件（`.md` / `.txt` / `.pdf`），复用现有对象存储与上传链路

**分块规则**：
- 优先按 Markdown 标题结构分段，其余按固定长度（如 800 字符）与重叠（如 80 字符）切分
- 每块记录来源文档、序号、原文

**验收标准**：
- 上传/粘贴后生成文档记录，可见分块列表与原文
- 分块失败（空文档、解析失败）给出明确错误
- 文档可删除，删除后其 chunk 不再参与抽取与检索

### 3.3 实体与关系抽取

**功能描述**：对文档分块运行 LLM 抽取，产出实体（节点）与关系（边），写入图谱。

**抽取输出（三元组）**：
- **实体**：名称、类型（人物/组织/产品/概念/事件等）、一句话描述
- **关系**：来源实体、目标实体、关系类型（如 `开发`、`属于`、`依赖`）、描述、置信度（0-1）

**抽取机制**：
- 手动触发：知识库详情页点击"开始抽取"，可选定指定文档或全量
- 上传后可选自动触发
- 抽取任务异步执行，任务状态机：`pending → running → done / failed`，失败记录原因可重试
- 抽取调用的 LLM 复用现有 `llm/client.py`，模型默认取系统默认模型，可逐知识库覆盖

**实体去重**：同一租户内同名（归一化后）实体合并为同一节点，关系去重（同源同目标同类型只保留置信度最高者）。

**人工复核**：
- 抽取结果写入"待确认"状态，管理员可逐条采纳/拒绝/编辑
- 已采纳的实体与关系进入正式图谱
- 支持批量采纳与一键全部采纳

**验收标准**：
- 上传一份含人物/组织关系的文档，抽取后能生成正确的实体与关系
- 抽取过程可在页面看到任务进度（处理 chunk 数 / 失败数）
- 抽取失败可查看原因并重试
- 同名实体自动合并，不产生重复节点
- 管理员可编辑实体名称/类型/描述，可删除错误关系

### 3.4 图谱可视化

**功能描述**：以节点-边图形式展示知识库的图谱，支持浏览与聚焦。

**交互**：
- 全图浏览，节点按实体类型着色，边按关系类型着色
- 搜索实体名并聚焦（高亮该实体及其 1-2 跳邻域）
- 按实体类型 / 关系类型筛选
- 点击节点查看实体详情与关联关系
- 布局：力导向图；图谱过大时限制渲染规模（如最多渲染 500 节点）

**验收标准**：
- 能渲染 ≥ 100 节点 / 200 边的图谱
- 实体搜索能定位并聚焦对应节点
- 筛选后视图可读、不卡死

### 3.5 图谱检索

**功能描述**：给定查询，检索出相关子图作为上下文。这是 Agent 消费图谱的入口。

**检索流程**：
1. **实体链接**：对查询做 jieba 分词（复用 `memory/service.py` 的 `_tokenize`），用 `pg_trgm` 相似度在实体名上模糊匹配 Top-K 候选实体
2. **子图展开**：以命中的实体为起点，用递归 CTE 做 1-3 跳邻域扩展，限制每跳数量防止爆炸
3. **序列化**：将子图整理为结构化文本（实体清单 + 三元组清单），按与查询的相关度排序
4. **上下文注入**：序列化结果作为上下文注入 Agent 的 system/user message

**辅助能力**：
- 提供检索测试页（交互复用现有知识库的"检索测试"），展示命中的实体、子图三元组、耗时
- 支持配置：展开跳数（默认 2）、每跳节点上限、实体链接 Top-K

**验收标准**：
- 查询"X 的负责人是谁"，若图谱中有 `X -负责-> 张三`，能召回该三元组
- 查询"A 间接依赖哪些组件"，能沿 2-3 跳关系链召回
- 检索结果可读、可溯源到原始 chunk
- 检索失败时 Agent 优雅降级，不影响对话

### 3.6 Agent 绑定与对话注入

**功能描述**：为 Agent 绑定图谱知识库，使 Agent 在对话中可检索图谱。

- 在 Agent 配置侧边栏新增"图谱知识库"绑定区块（与现有"知识库"绑定交互一致，可多选）
- 绑定后注入 `graph_retrieval` 工具（与现有 `knowledge_retrieval` 并列）
- 绑定关系存 `agent_graph_knowledge_bases` 关联表
- 未绑定图谱知识库的 Agent 不注入该工具

**验收标准**：
- 可在 Agent 配置页绑定/解绑图谱知识库
- 绑定后 Agent 对话能调用图谱检索工具并引用检索结果
- 与现有 RAGFlow 知识库可同时绑定、互不冲突

### 3.7 菜单与入口改造

**功能描述**：将现有"知识库"升级为父级菜单，原 RAGFlow 知识库变为其子菜单。

**菜单结构**：

```
资源与集成
└── 知识库（父级，可展开）
    ├── 知识图谱（新，/knowledge-graph）
    └── RAGFlow 知识库（原 /knowledge，重命名）
```

**验收标准**：
- 侧边栏"知识库"可展开/折叠，默认展开当前所在子页
- 原 `/knowledge` 路径与页面内容不变，仅菜单名改为"RAGFlow 知识库"
- 新"知识图谱"入口指向新页面

## 四、数据模型（草案）

沿用现有 `db/models.py` 风格：无外键约束、应用层维护归属关系，资源级表含 `tenant_id`、`created_by`、`visibility`。

## 五、技术方案要点

### 5.1 存储

- **PostgreSQL 关系表**存储图谱，不引入新数据库（不使用 Neo4j），理由：图谱规模为百万级节点内、遍历深度浅（1-3 跳），关系表 + 递归 CTE 足够，且复用现有部署、备份、租户隔离。
- 实体名建 **pg_trgm GIN 索引**（复用已有 `pg_trgm` 扩展）做模糊实体链接；关系类型、实体类型建普通 B-tree 索引。
- 全文检索可选启用 `tsvector`，Phase 2 再评估。

### 5.2 图谱遍历

- 多跳遍历用 **`WITH RECURSIVE` 递归 CTE**，层数上限（默认 3）与每层分支上限防止组合爆炸。
- 示例（伪代码）：
  ```sql
  WITH RECURSIVE subgraph AS (
    SELECT * FROM graph_relationships WHERE source_entity_id = ANY(:seeds)
    UNION ALL
    SELECT r.* FROM graph_relationships r
    JOIN subgraph s ON r.source_entity_id = s.target_entity_id
    WHERE depth < :max_depth
  ) SELECT ... ;
  ```

### 5.3 实体链接

- 复用 `memory/service.py` 的 jieba 分词，对实体名与查询词做 `pg_trgm` 相似度匹配，Top-K 作为子图起点。
- 实体名归一化（去空白、统一大小写）保证库内唯一。

### 5.4 LLM 抽取

- 复用 `llm/client.py`，按 chunk 批量抽取，Prompt 要求输出结构化 JSON（实体数组 + 关系数组，含类型与置信度）。
- 输出用 Pydantic 校验，非法输出丢弃该 chunk 并计数。
- 异步执行：进程内后台任务（asyncio 队列 / APScheduler 触发），状态写入 `graph_extraction_jobs`，与现有 `cron_jobs` 调度模式一致，不引入 Celery。

### 5.5 图谱可视化

- 前端引入 **AntV G6**（或 vis-network），在详情页渲染节点-边图。
- 服务端提供子图查询接口（给定实体 ID 集合与跳数，返回节点 + 边），前端只做渲染，避免全图数据量过大。

### 5.6 多租户与安全

- 全部表按 `tenant_id` + `visibility` + `created_by` 应用层过滤，与现有 `_knowledge_base_visible_to` 一致。
- 抽取任务、检索接口走 `AdminUser` / 认证依赖。

## 六、非功能需求

### 6.1 性能

- 单次子图检索（3 跳内）响应时间 < 2 秒
- 单文档（≤ 1000 chunk）全量抽取在 10 分钟内完成（受 LLM 限速约束）
- 图谱可视化渲染规模上限 500 节点 / 1000 边

### 6.2 可用性

- 抽取任务失败不阻塞其他功能，可重试
- 图谱检索失败时 Agent 优雅降级

### 6.3 安全性

- 多租户隔离：所有图谱数据按租户过滤，跨租户不可见
- 上传文档大小限制（默认 10MB）
- 抽取与检索接口鉴权

### 6.4 可扩展性

- 表结构与检索逻辑与 RAGFlow 解耦，后续可增量引入 pgvector 语义检索（Phase 3）
- 实体类型、关系类型不硬编码，由抽取产出，可在前端维护类型字典

## 七、界面设计要点

### 7.1 菜单

- 侧边栏"知识库"为可展开父级：子项"知识图谱"（/knowledge-graph）、"RAGFlow 知识库"（/knowledge）

### 7.2 知识图谱列表页（/knowledge-graph）

- 顶部：新建图谱知识库按钮
- 主体：图谱知识库卡片列表（名称、描述、实体数、关系数、启用状态、操作）

### 7.3 图谱知识库详情页

Tab 结构：
- **图谱**：G6 图视图 + 实体搜索框 + 类型筛选
- **文档**：文档列表 + 上传/粘贴入口 + 分块查看
- **实体**：实体表格（名称/类型/描述/状态），支持编辑、删除、批量采纳
- **关系**：关系表格（源/关系/目标/置信度/状态），支持编辑、删除
- **抽取**：抽取任务列表（状态、进度、失败原因、重试按钮）+ 触发抽取按钮
- **检索测试**：输入查询，展示命中实体 + 子图三元组 + 耗时（复用现有检索测试交互）

## 八、验收标准汇总

1. 菜单改造完成："知识库"含"知识图谱"与"RAGFlow 知识库"两个子菜单，原路径 `/knowledge` 可用。
2. 图谱知识库可 CRUD，租户隔离生效。
3. 上传文档自动分块，分块可见。
4. LLM 抽取产出实体与关系，任务进度可见，失败可重试，同名实体合并。
5. 实体与关系可人工复核（采纳/编辑/删除）。
6. 图谱可视化可渲染、可搜索聚焦、可筛选。
7. 检索测试可召回子图三元组并可溯源到 chunk。
8. Agent 可绑定图谱知识库并在对话中检索。

## 十、术语表

| 术语 | 说明 |
|---|---|
| 图谱知识库（Graph KB） | 以实体-关系图形式组织知识的资源单元 |
| 实体（Entity） | 图节点，如人物、组织、产品、概念 |
| 关系（Relationship） | 图边，如"开发""属于""依赖"，连接两个实体 |
| 三元组（Triple） | 主语-谓语-宾语，即 源实体-关系-目标实体 |
| 子图（Subgraph） | 从若干实体出发沿关系扩展得到的局部图 |
| 实体链接（Entity Linking） | 将查询文本映射到图谱中的实体 |
| 抽取管线（Extraction Pipeline） | 文档分块 → LLM 抽取 → 去重 → 人工复核 的流程 |
