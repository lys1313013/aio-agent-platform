# 自定义远程工具（HTTP 工具）需求与技术方案

> 本文档定义 AIO Agent Platform 的"自定义远程工具"功能需求和技术设计。
> 允许管理员通过 Web UI 配置任意 REST API 端点为 Agent 可调用工具,无需编写代码,无需 MCP 协议。

---

## 1. 概述

### 1.1 背景与动机

当前系统接入外部服务有两种方式:

| 方式 | 优点 | 缺点 |
|------|------|------|
| **硬编码工具** | 灵活、可控 | 每接一个 API 都要改代码、发版 |
| **MCP 协议** | 标准、生态丰富 | 要求对方实现 MCP Server,很多企业 API 不提供 |

**缺口**:大量第三方服务(JIRA、企业微信、飞书、内部中台、BI 平台、工单系统等)只暴露普通 REST API,既没有 MCP Server,也不值得为它们各写一段硬编码。

**目标**:让管理员在 Web UI 填一张表,就能把一个 REST API 端点注册为 Agent 工具,Agent 调用时自动发 HTTP 请求、解析响应、返回结果。

### 1.2 核心原则

- **零代码接入**:管理员通过配置完成,不需要写 Python/不需要发版
- **与内置工具无差异**:LLM 视角下,远程工具与内置工具完全一致(function calling)
- **安全可控**:管理员才能配置;敏感信息(凭证)加密存储;支持 URL 白名单
- **灵活映射**:支持 URL 模板变量、请求体模板、Header 注入、响应提取

### 1.3 与 MCP 的关系

| 维度 | MCP 工具 | 自定义远程工具 |
|------|----------|----------------|
| 对方要求 | 必须实现 MCP 协议 | 任意 REST/HTTP API |
| 工具发现 | 自动(list_tools) | 管理员手动配置 |
| 参数 Schema | 自动获取 | 管理员手动定义 |
| 适用场景 | 对方提供 MCP Server | 对方只提供普通 API |
| 复杂度 | 低(配置 URL 即可) | 中(需配置参数映射) |

两者互补,共存于同一 Agent 工具选择面板。

## 4. 数据模型

### 4.1 remote_tools 表

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| id | UUID | ✓ | 主键 |
| name | VARCHAR(64) | ✓ | 工具名称(LLM 可见,需符合 function name 规范: `^[a-zA-Z0-9_-]+$`) |
| description | TEXT | ✓ | 工具描述(LLM 可见,指导何时调用) |
| method | VARCHAR(10) | ✓ | HTTP 方法: GET / POST / PUT / DELETE / PATCH |
| url_template | VARCHAR(1024) | ✓ | URL 模板,如 `https://api.example.com/users/{user_id}` |
| parameters_schema | JSONB | ✓ | JSON Schema,定义 LLM 需要传入的参数 |
| headers | JSONB | | 静态请求头(不含认证头),如 `{"Accept": "application/json"}` |
| auth_type | VARCHAR(32) | ✓ | 认证类型: none / bearer / api_key / basic / custom_header |
| auth_config | JSONB | | 认证配置(加密存储),结构见 §4.2 |
| query_params | JSONB | | Query 参数映射,如 `{"page": "page_num", "size": "page_size"}` |
| body_template | JSONB | | POST/PUT 请求体模板,支持 `{{变量名}}` 插值 |
| response_extract | VARCHAR(256) | | 响应 JSONPath 提取表达式,如 `$.data.items[*]` |
| timeout | INTEGER | ✓ | 超时时间(秒),默认 30,范围 5-600 |
| is_active | BOOLEAN | ✓ | 是否启用,默认 true |
| created_at | TIMESTAMPTZ | ✓ | 创建时间 |
| updated_at | TIMESTAMPTZ | ✓ | 更新时间 |

### 4.2 auth_config 结构

根据 `auth_type` 不同,`auth_config` 存储不同结构:

```
auth_type = "none"        →  {}
auth_type = "bearer"      →  { "token": "sk-xxxxx" }
auth_type = "api_key"     →  { "header_name": "X-API-Key", "key": "xxxxx" }
auth_type = "basic"       →  { "username": "user", "password": "pass" }
auth_type = "custom_header" → { "headers": { "X-Token": "xxx", "X-Org-Id": "123" } }
```

所有敏感字段(`token`、`key`、`password`、`headers` 中的值)在存储时加密,读取时解密。

### 4.3 name 唯一约束

`name` 在全局工具空间(builtin + mcp + remote)中必须唯一。创建时检查:
- 不与内置工具名冲突(run_shell、read_file 等)
- 不与已有 MCP 工具名冲突(含 tool_prefix)
- 不与已有远程工具名冲突

## 5. 技术方案

### 5.1 架构概览

```
┌─────────────────────────────────────────────────────────────────┐
│                       ToolExecutor.execute()                    │
│                                                                 │
│  tool_name ──→ 1. MCP tool?     ──→ MCPManager.call_tool()     │
│            ──→ 2. Remote tool?  ──→ RemoteToolExecutor.call()   │  ← 新增
│            ──→ 3. Built-in tool ──→ sandbox / direct handler    │
└─────────────────────────────────────────────────────────────────┘
```

### 5.2 新增模块

```
backend/src/aio_agent/tools/remote/
├── __init__.py          # 模块入口
├── executor.py          # RemoteToolExecutor — HTTP 请求构建与执行
├── template.py          # URL 模板变量替换 + 请求体模板插值
└── manager.py           # RemoteToolManager — 生命周期管理、DB CRUD、注册到 ToolRegistry
```

### 5.3 RemoteToolManager

职责:
- 启动时从 DB 加载所有 `is_active=true` 的远程工具
- 为每个远程工具生成 `Tool` 对象,注册到 `ToolRegistry`
- 提供 `is_remote_tool(name)` 判断
- 提供 CRUD 方法(创建/更新/删除后自动重新注册)

```python
class RemoteToolManager:
    def __init__(self, registry: ToolRegistry):
        self._registry = registry
        self._tools: dict[str, RemoteToolConfig] = {}  # name → DB config

    async def initialize(self):
        """启动时加载所有 active 远程工具并注册"""

    async def create_tool(self, config: dict) -> RemoteToolConfig:
        """创建工具:写 DB → 注册到 registry"""

    async def update_tool(self, tool_id: UUID, config: dict) -> RemoteToolConfig:
        """更新工具:写 DB → 重新注册"""

    async def delete_tool(self, tool_id: UUID):
        """删除工具:从 registry 注销 → 删 DB"""

    def is_remote_tool(self, name: str) -> bool:
        """判断是否为远程工具"""

    def get_config(self, name: str) -> RemoteToolConfig | None:
        """获取工具配置(含 URL、认证等)"""
```

### 5.4 RemoteToolExecutor

职责:根据工具配置 + LLM 传入参数,构建并发送 HTTP 请求。

```python
class RemoteToolExecutor:
    async def call(self, tool_name: str, arguments: dict) -> str:
        """
        执行流程:
        1. 从 RemoteToolManager 获取工具配置
        2. URL 模板替换(路径变量)
        3. 构建 Query 参数
        4. 构建请求头(静态 + 认证)
        5. 构建请求体(模板插值)
        6. 发送 HTTP 请求
        7. 响应提取(JSONPath)
        8. 序列化为字符串返回
        """
```

### 5.5 URL 模板替换

支持 `{variable_name}` 语法,变量从 LLM 参数中提取:

```
url_template: "https://api.example.com/users/{user_id}/orders/{order_id}"
arguments:    { "user_id": "u-123", "order_id": "o-456", "status": "paid" }

→ URL: "https://api.example.com/users/u-123/orders/o-456"
→ 剩余参数(非路径变量):{ "status": "paid" } → 可用于 query 或 body
```

### 5.6 请求体模板

`body_template` 支持 `{{variable_name}}` 插值:

```json
// 配置
{
  "body_template": {
    "rid": "{{rid}}",
    "data": {
      "name": "{{name}}",
      "status": "{{status}}"
    }
  }
}

// LLM 参数
{ "rid": "ri.xxx", "name": "test", "status": "start" }

// 实际请求体
{
  "rid": "ri.xxx",
  "data": {
    "name": "test",
    "status": "start"
  }
}
```

对于不需要模板的简单场景,可以直接把 LLM 参数作为请求体(`body_template` 留空时,非路径变量全部放入 body)。

### 5.7 Query 参数映射

`query_params` 定义工具参数名 → URL query 参数名的映射:

```json
// 配置
{ "query_params": { "page": "page", "page_size": "pageSize" } }

// LLM 参数
{ "page": 2, "page_size": 20, "keyword": "test" }

// URL: ?page=2&pageSize=20
// 剩余参数:{ "keyword": "test" } → 如果有 body_template 则放入 body
```

未出现在 `query_params` 中的参数:
- GET/DELETE → 自动追加到 query string
- POST/PUT/PATCH → 放入 body(如果 `body_template` 为空)

### 5.8 响应提取

支持简单 JSONPath 语法,只返回有用部分:

| 表达式 | 含义 |
|--------|------|
| `$` | 整个响应 |
| `$.data` | 取 data 字段 |
| `$.data.items[*]` | 取 data.items 数组 |
| `$.data.items[*].name` | 取每个 item 的 name |

留空时返回整个响应 JSON。

### 5.9 执行流程示例

以"查询 JIRA issue"为例:

**管理员配置:**
```json
{
  "name": "jira_get_issue",
  "description": "Get a JIRA issue by key. Use when user asks about a specific ticket.",
  "method": "GET",
  "url_template": "https://jira.example.com/rest/api/3/issue/{issue_key}",
  "parameters_schema": {
    "type": "object",
    "properties": {
      "issue_key": { "type": "string", "description": "JIRA issue key, e.g. PROJ-123" }
    },
    "required": ["issue_key"]
  },
  "auth_type": "bearer",
  "auth_config": { "token": "eyJhbGc..." },
  "headers": { "Accept": "application/json" },
  "response_extract": "$.fields",
  "timeout": 30
}
```

**Agent 调用:**
```json
{ "tool": "jira_get_issue", "arguments": { "issue_key": "PROJ-123" } }
```

**执行过程:**
1. URL 替换: `https://jira.example.com/rest/api/3/issue/PROJ-123`
2. 请求头: `{ "Accept": "application/json", "Authorization": "Bearer eyJhbGc..." }`
3. 发送 GET 请求
4. 响应提取: `$.fields` → 只返回 issue fields 部分
5. 序列化为 JSON 字符串返回给 Agent

## 8. ToolExecutor 集成

### 8.1 路由变更

在 `ToolExecutor.execute()` 中新增远程工具路由(在 MCP 之后、Built-in 之前):

```python
async def execute(self, tool_name, arguments, ...):
    # 1. MCP tool routing
    if self.mcp_manager and self.mcp_manager.is_mcp_tool(tool_name):
        ...

    # 2. Remote tool routing  ← 新增
    if self.remote_manager and self.remote_manager.is_remote_tool(tool_name):
        try:
            output = await self.remote_executor.call(tool_name, arguments)
            output = self._truncate(output)
            return ToolResult(
                tool_call_id=tool_call_id,
                name=tool_name,
                arguments=arguments,
                output=output,
                success=True,
                duration_ms=(time.monotonic() - t_start) * 1000,
            )
        except Exception as e:
            return ToolResult(
                ...,
                success=False,
                error=f"Remote tool error: {e}",
            )

    # 3. Built-in tool routing
    tool = self.registry.get(tool_name)
    ...
```

### 9.1 管理页面

新增管理页面"远程工具",与 MCP 管理页面平级,位于管理员侧边栏。

**列表视图:**
- 卡片网格展示(与 MCP 页面风格一致)

**创建/编辑表单:**

1. **基本信息**:名称、描述、HTTP Method、URL 模板

4. **认证与安全**:认证类型选择、凭证输入、超时时间

**测试面板:**

## 11. 配置示例

### 11.1 调用外部 LLM/OCR 服务（凭证图片识别）

**场景**:调用兼容 OpenAI Chat Completions 格式的外部 AI 服务,对凭证图片进行 OCR 识别。

**原始 curl 请求:**

```bash
curl --location --request POST 'https://chat.api.example.com/v1/chat/completions' \
--header 'Authorization: Bearer your-api-token-here' \
--header 'Content-Type: application/json' \
--data-raw '{
  "model": "voucher-ocr-model",
  "messages": [
    {
      "role": "user",
      "content": [
        {
          "type": "image_url",
          "image_url": {
            "url": "xxx"
          }
        }
      ]
    }
  ]
}'
```

**远程工具配置:**

```json
{
  "name": "voucher_ocr",
  "description": "对凭证/发票图片进行 OCR 识别,提取关键字段(金额、日期、凭证号等)。当用户提供凭证图片 URL 并需要识别内容时调用此工具。",
  "method": "POST",
  "url_template": "https://chat.api.example.com/v1/chat/completions",
  "parameters_schema": {
    "type": "object",
    "properties": {
      "image_url": {
        "type": "string",
        "description": "凭证图片的 URL 地址,支持 base64 data URI 或 HTTP(S) 链接"
      },
      "prompt": {
        "type": "string",
        "description": "可选的提示词,用于指导 OCR 识别重点,默认: '请识别该凭证图片中的所有关键信息'",
        "default": "请识别该凭证图片中的所有关键信息"
      }
    },
    "required": ["image_url"]
  },
  "headers": {
    "Content-Type": "application/json"
  },
  "auth_type": "bearer",
  "auth_config": {
    "token": "your-api-token-here"
  },
  "body_template": {
    "model": "voucher-ocr-model",
    "messages": [
      {
        "role": "user",
        "content": [
          {
            "type": "text",
            "text": "{{prompt}}"
          },
          {
            "type": "image_url",
            "image_url": {
              "url": "{{image_url}}"
            }
          }
        ]
      }
    ]
  },
  "response_extract": "$.choices[0].message.content",
  "timeout": 60
}
```

**配置要点说明:**

| 配置项 | 值 | 说明 |
|--------|-----|------|
| `method` | POST | Chat Completions API 固定 POST |
| `url_template` | 无路径变量 | URL 固定,无需模板替换 |
| `auth_type` | bearer | 自动注入 `Authorization: Bearer <token>` |
| `headers` | Content-Type | 静态 Header,认证 Header 由 auth 自动处理 |
| `body_template` | 嵌套模板 | 支持深层嵌套 JSON 中的 `{{变量}}` 插值 |
| `response_extract` | `$.choices[0].message.content` | 只提取 LLM 返回的文本内容,忽略 usage/token 等元数据 |
| `timeout` | 60s | OCR 模型处理图片耗时较长,适当增大超时 |

**Agent 调用示例:**

```json
{
  "tool": "voucher_ocr",
  "arguments": {
    "image_url": "https://storage.example.com/invoices/2024-001.jpg",
    "prompt": "请提取该发票的发票号、金额、税额、开票日期"
  }
}
```

**执行过程:**

1. **URL**:直接使用 `https://chat.api.example.com/v1/chat/completions`(无路径变量)
2. **请求头构建**:
   ```
   Content-Type: application/json          ← 来自 headers
   Authorization: Bearer your-api-token-here ← 来自 auth_type=bearer + auth_config.token
   ```
3. **请求体构建**(模板插值后):
   ```json
   {
     "model": "voucher-ocr-model",
     "messages": [
       {
         "role": "user",
         "content": [
           {
             "type": "text",
             "text": "请提取该发票的发票号、金额、税额、开票日期"
           },
           {
             "type": "image_url",
             "image_url": {
               "url": "https://storage.example.com/invoices/2024-001.jpg"
             }
           }
         ]
       }
     ]
   }
   ```
4. **发送 POST 请求**,等待响应
5. **响应提取**: `$.choices[0].message.content` → 只返回 OCR 识别结果文本
6. 返回给 Agent,Agent 基于识别结果回答用户

**嵌套模板插值说明:**

此示例展示了 `body_template` 对深层嵌套 JSON 的支持。模板引擎会递归遍历整个 JSON 结构,对所有字符串值中的 `{{变量名}}` 进行替换:

```
body_template 中的:  "{{image_url}}"
                      ↓ 从 arguments 中取值
替换后:              "https://storage.example.com/invoices/2024-001.jpg"

body_template 中的:  "{{prompt}}"
                      ↓ 从 arguments 中取值(未传则用 default)
替换后:              "请提取该发票的发票号、金额、税额、开票日期"
```

**变体:支持多图片识别**

如果需要一次传入多张图片,可以调整 `parameters_schema` 和 `body_template`:

```json
{
  "parameters_schema": {
    "type": "object",
    "properties": {
      "image_urls": {
        "type": "array",
        "items": { "type": "string" },
        "description": "凭证图片 URL 列表"
      }
    },
    "required": ["image_urls"]
  },
  "body_template": {
    "model": "voucher-ocr-model",
    "messages": [
      {
        "role": "user",
        "content": "{{image_urls}}"
      }
    ]
  }
}
```

> **注意**:数组类型变量的模板插值需要特殊处理——当 `{{image_urls}}` 的值是数组时,引擎将其展开为 OpenAI Vision 格式的 content 数组:
> ```json
> [
>   { "type": "image_url", "image_url": { "url": "https://..." } },
>   { "type": "image_url", "image_url": { "url": "https://..." } }
> ]
> ```
