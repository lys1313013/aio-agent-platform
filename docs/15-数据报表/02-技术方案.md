## 1. 后端接口设计

统一前缀 `/api/analytics`，鉴权沿用现有 JWT。

| 接口 | 说明 |
|---|---|
| `GET /api/analytics/summary?start=&end=` | 指标卡数据 + 环比 |
| `GET /api/analytics/trend?metric=tokens\|sessions&start=&end=&granularity=day` | 趋势序列 |
| `GET /api/analytics/distribution?by=model\|agent&start=&end=` | 分布数据 |
| `GET /api/analytics/detail?start=&end=&page=` | 按日 × 模型明细分页 |
| `GET /api/analytics/export?start=&end=` | CSV 导出 |
| `GET /api/admin/analytics/...` | 管理员全局视图接口（供 `/usage` 页切换调用），去掉 user_id 过滤，支持按用户筛选 |

**数据写入（前置任务）：**

- 在 `AgentLoop` 收到每次 LLM 响应的 usage 后，异步 upsert `token_usage_daily`（`ON CONFLICT (user_id, date, model) DO UPDATE` 累加）。
- 不计算费用：`cost_usd` 写入时保持 0。

## 2. 技术要点

- **图表库**：前端尚未引入图表库，推荐 `@ant-design/plots`（G2 封装，与 AntD 6 风格统一）。
- **查询性能**：趋势/分布全部查 `token_usage_daily` 预聚合表；会话数趋势查 `sessions` 按 `created_at::date` 分组（加索引或在数据量大后建物化视图）。
- **环比计算**：上一周期取等长的前一时间窗，接口内完成。
- **时区**：`token_usage_daily.date` 按服务器日期统计，前端按本地时区展示即可，MVP 不做时区对齐。
- **权限**：普通接口强制 `current_user_id` 过滤；admin 接口校验角色。
