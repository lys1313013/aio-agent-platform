# AIO Agent Platform — 产品需求文档 (PRD)

> 多租户自进化 AI 智能体平台，支持多智能体委派、知识库检索、MCP 协议、自定义远程工具、消息队列驱动任务编排。

---

## 1. 项目概述

### 1.1 愿景

构建一个**多租户、自托管、自进化**的 AI 智能体平台，核心理念：

- 记住与用户的每一次交互中提取的关键信息（按用户隔离）
- 从成功完成的任务中自动提炼可复用的「技能」
- 通过工具系统与外部世界交互（搜索、执行代码、操作文件等）
- 支持多智能体层次化委派（DAG 结构），实现复杂任务的并行分解
- **支持多个用户同时使用**，每个用户的数据完全隔离

### 1.2 目标用户

- 团队 / 企业：统一部署智能体平台，多个成员各自拥有独立 Agent 空间
- 开发者：用自然语言完成编码、调试、部署等任务
- 业务人员：通过智能体完成报销、审批、数据查询等业务流程
- 平台管理员：管理模型供应商、MCP 服务器、知识库、远程工具等平台资源

### 1.3 核心差异化

| 特性 | 普通 Chatbot | 本项目 |
|------|-------------|--------|
| 多租户 | 单用户或无隔离 | 完整多租户隔离，PostgreSQL RLS + user_id 过滤 |
| 记忆 | 仅当前对话 | 三层持久记忆架构（L1 常驻 / L2 长期 / L3 情景），按用户隔离 |
| 学习 | 无 | 从任务中提取可复用技能，版本化管理，支持公共技能共享 |
| 工具 | 有限 | 24 个内置工具 + MCP 协议 + 自定义远程 HTTP 工具 |
| 多智能体 | 无 | DAG 层次化委派，子智能体并行执行，父智能体汇总 |
| 主动性 | 被动响应 | Webhook 驱动异步任务 + 定时任务 |
| 知识库 | 无 | RAGFlow 集成，按智能体绑定，检索增强生成 |
| 沙盒安全 | 无或弱 | Docker 容器隔离，只读根文件系统，cap_drop=ALL，非 root 运行 |
| 交互确认 | 不支持 | 5 种确认模式（单选/多选/自由输入/审批/表格录入），支持暂停-恢复 |

## 4. 功能详细需求

### F1. Agent Loop（核心推理循环）

> 智能体的大脑，负责「理解 → 规划 → 执行 → 观察」的闭环。

**优先级：P0 | 状态：✅ 已实现**

#### F1.1 ReAct 循环

- [x] 支持多轮工具调用，支持配置主子智能体迭代次数
- [x] 每次迭代包含：推理（thinking）、工具调用（tool_call）、观察（observation）
- [x] 当 LLM 不再调用工具时，循环结束并返回最终回答
- [x] 超过最大迭代次数时，返回当前进度并提示用户
- [x] 流式过程中如果 LLM 返回工具调用，正确切换到工具执行流程
- [x] 工具调用失败时，将错误作为 observation 返回给 LLM，让其自行纠正

#### F1.2 动态 Prompt 组装

- [x] System Prompt 由以下部分按优先级组装：L1 常驻记忆 > 相关技能 > 子智能体列表 > 工作区文件 > 工具描述
- [x] 上下文窗口超限时，自动压缩历史消息（三级压缩策略：轻量截断 → LLM 摘要 → 紧急压缩）
- [x] 支持 Jinja2 模板渲染（`system_prompt.j2`、`memory_writer.j2`、`context_summary.j2`）
- [x] Token 估算支持中英文混合（CJK ~1.5 chars/token，Latin ~4 chars/token）

#### F1.3 流式输出

- [x] REST SSE（Server-Sent Events）和 WebSocket 双通道
- [x] SSE 事件类型：`text_delta`、`reasoning`、`tool_call`、`tool_result`、`delegation_*`、`confirmation_*`
- [x] 子智能体事件通过事件队列代理到父智能体的 SSE 流
- [x] 客户端断开时，部分消息保存防止数据丢失

#### F1.4 多模型支持

- [x] OpenAI Provider：兼容所有 OpenAI Chat Completions API 的服务（DeepSeek、OpenRouter、Ollama、vLLM 等）
- [x] Anthropic Provider：使用 Anthropic Messages API 原生格式（支持 system 独立参数、tool_use block）
- [x] 工具调用（function calling / tool use）在两种协议间行为一致
- [x] 多模态支持：图片通过 base64 data URI 注入，自动压缩（Pillow resize 2048px + JPEG quality 85）
- [x] 管理员在 Web UI 中管理供应商和模型，设置全局默认模型
- [ ] 优雅处理模型不支持 tool calling 的情况（降级为文本指令）

#### F1.5 错误恢复

- [x] 工具调用失败时，将错误信息作为 observation 返回给 LLM
- [x] LLM API 调用失败时，支持自动重试（最多 3 次，指数退避 1s→2s→4s）
- [ ] 连续 3 次工具调用失败时，暂停并向用户报告
- [x] 所有异常都有结构化日志记录

### F2. 记忆系统（Memory System）

> 让 Agent 具备跨会话的持久记忆能力，所有数据按用户 ID 隔离。

**优先级：P0 | 状态：✅ 主要功能已实现**

#### F2.1 三层记忆架构

| 层级 | 名称 | 存储内容 | 检索方式 | 加载时机 |
|------|------|---------|---------|---------|
| L1 | 常驻上下文 | 用户偏好、项目规则、核心事实 | 全量加载 | 每次对话开始 |
| L2 | 长期记忆 | 历史决策、经验教训、重要事件 | pg_trgm 相似度检索 (jieba 分词) | 按 Top-K 注入 |
| L3 | 情景记忆 | 每日对话摘要 | 相关性 + 时间衰减 | 按需检索 |

- [x] L1 记忆存储在 `memories` 表，`layer=L1`，每次对话全量注入
- [x] L2 记忆通过 pg_trgm + jieba 中文分词做相似度检索，Top-K 注入（K 可配置，默认 5）
- [x] L3 记忆按相关性和时间排序，去重后注入
- [x] 所有记忆查询和写入自动附加 `user_id` 过滤
- [x] Web UI 按层级分 Tab 展示，支持搜索、在线编辑、删除
- [ ] 预留 `SearchBackend` 抽象接口，后续可升级为向量语义检索

#### F2.2 记忆写入

- [x] 对话结束后，LLM 自动判断是否需要提取记忆（后台异步任务，fire-and-forget）
- [x] 用户可通过指令显式触发记忆写入
- [x] 记忆写入时自动分类到对应层级，关联当前 `user_id`
- [x] 提取前守卫检查：至少 2 条历史消息且长度满足最小阈值
- [ ] 写入时检查是否与已有记忆冲突，如有则更新而非重复添加

#### F2.3 记忆检索

- [x] pg_trgm 全文检索：基于 PostgreSQL trigram 相似度 + jieba 分词
- [x] 关键词检索：ILIKE 模糊匹配
- [x] 所有检索自动附加 `WHERE user_id = ?` 条件
- [ ] 时间检索：按日期范围过滤情景记忆
- [ ] 预留 `SearchBackend` 抽象接口，后续可引入向量语义检索

#### F2.4 记忆压缩与维护

- [x] 每日对话自动摘要后存储（LLM 驱动的 memory extraction）
- [x] L1 常驻上下文通过 Token 预算管理自动裁剪
- [ ] 支持手动触发记忆整理（合并重复、删除过时）
- [ ] 管理员可查看各用户的记忆存储用量

### F3. 技能系统（Skill System）

> 自学习闭环 — Agent 从完成任务中提取可复用的方法论，支持文件打包和版本管理。

**优先级：P1 | 状态：✅ 已实现**

#### F3.1 技能定义

- [x] 技能存储在 `skills` 表，包含名称、描述、标签（JSONB）、类别、触发条件
- [x] 技能包通过 MinIO 存储（zip 格式），包含 SKILL.md + scripts/ + references/ + assets/
- [x] 每条技能关联 `user_id`，用户只能看到和管理自己的技能
- [x] 支持版本管理：更新时自动归档旧版本到 `skill_versions` 表
- [x] 管理员可将技能标记为"平台公共技能"（`is_public`），所有用户可见
- [x] 追踪 `use_count`、`success_count`、`success_rate`、`last_used_at` 元数据
- [x] Web UI：卡片网格展示、标签筛选、关键词搜索、在线 Markdown 编辑器 + 实时预览
- [x] Web UI：技能文件浏览器（树状视图）、附属文件拖拽上传（scripts/references/assets）
- [x] 支持 zip 导入/导出

#### F3.2 技能检索与调用

- [x] 用户输入经过分词后与技能库做 pg_trgm 相似度匹配
- [x] 检索范围包含用户私有技能 + 平台公共技能
- [x] Top-3 相关技能注入 System Prompt
- [x] `view_skill` 工具自动将技能文件部署到沙盒 `/workspace/skills/{name}/`
- [x] Agent 可通过 `report_skill_result` 记录技能执行结果
- [ ] 技能执行完成后记录成功/失败，用于后续优化
- [x] 执行日志记录完整执行链（`execution_log` JSONB）

#### F3.3 技能自动提取

- [ ] 任务完成后，Agent 自评：步骤数 ≥ 3 且包含工具调用 → 触发技能提取
- [ ] 提取过程由 LLM 完成：总结步骤、提炼注意事项、生成 SKILL.md
- [ ] 提取的技能需要用户确认后才保存（可配置为自动保存）

#### F3.4 技能迭代优化

- [x] `success_rate` 和 `last_used` 元数据自动维护
- [x] 技能更新时旧版本自动归档，支持版本回滚

#### F3.5 从 skills.sh 技能市场同步

- [x] 技能管理页新增「同步」入口，支持两种输入方式：
  - 粘贴单个 skills.sh 链接（如 `https://www.skills.sh/vercel-labs/skills/find-skills`）或 `owner/repo/skill` 引用，直接解析该技能
  - 输入关键词搜索 skills.sh 技能市场，结果以列表展示，勾选后可批量同步导入
- [x] 搜索结果展示仓库元信息：安装数、GitHub ⭐ stars、forks、仓库描述、编程语言、许可证
- [x] 技能内容通过 skills.sh 官方下载接口获取，不依赖 GitHub API（避免其按 IP 的限流）
- [x] 仓库元信息（stars/forks/描述/语言/许可证）通过 GitHub API 补充，进程内缓存 6 小时（失败结果仅缓存 5 分钟，避免限流锁死空数据）
- [x] 可选配置 `GITHUB_TOKEN` 提升 GitHub API 限流额度（匿名 60 次/小时/IP，带 token 5000 次/小时）；未配置或限流时自动回退到 shields.io 展示粗略数据（stars/forks 为缩写数字、许可证精确、无仓库描述与语言名），不影响搜索与导入
- [x] 单个技能文件总大小超过 10MB 时拒绝导入
- [x] 批量导入按条目逐个处理，单个失败不影响其他技能导入，返回失败明细

#### F4.3 工具执行引擎

- [x] 执行顺序：MCP 工具 → 远程 HTTP 工具 → 内置沙盒工具 → 内置直接处理器
- [x] 路径安全检查：解析后必须在 `/workspace` 内，禁止 `..` 穿越
- [x] 危险命令黑名单：拦截 `rm -rf /`、`mkfs`、`dd if=/dev/zero`、fork bomb 等
- [x] 工具输出截断：超过 10,000 字符自动截断
- [x] 每个工具有独立超时配置，超时自动终止
- [x] 同一会话内工具调用串行执行
- [x] 不同会话的工具调用可并发执行
- [ ] 每次工具调用生成结构化审计日志

#### F4.4 权限级别

## 8. 非功能性需求

| 维度 | 要求 |
|------|------|
| **多租户隔离** | 用户数据 100% 隔离，PostgreSQL RLS + user_id 双重保障 |
| **沙盒隔离** | 所有命令和文件操作在 Docker 容器内执行，零宿主机接触 |
| **沙盒安全** | 容器以非 root 运行，根文件系统只读，cap_drop=ALL，no-new-privileges |
| **认证安全** | 密码 bcrypt 加密，JWT HS256 签名，refresh token 轮转 + SHA-256 哈希 |
| **数据完整性** | NUL 字节自动清洗，乐观锁冲突重试，幂等去重 |
| **性能** | Web UI 首屏加载 < 2s，SSE 消息端到端延迟 < 100ms（不含 LLM） |
| **可靠性** | 子智能体异常不影响父智能体，MCP Server 崩溃不影响主进程，遗留沙盒自动清理 |
| **可扩展性** | 工具、技能、记忆后端均可扩展；处理器注册机制；SearchBackend 抽象接口预留 |
| **数据安全** | 所有数据本地存储（LLM API 除外），API Key 不暴露给 Agent |
| **兼容性** | Python >= 3.11，Node.js >= 20，PostgreSQL 16，Docker |
| **浏览器** | Chrome / Firefox / Safari / Edge 最新两个主版本 |
| **响应式** | 桌面端 >=1024px，移动端 >=375px 可用 |

## 9. 术语表

| 术语 | 定义 |
|------|------|
| **Agent Loop** | 智能体的核心推理-执行循环 |
| **ReAct** | Reasoning + Acting，交替推理与执行的范式 |
| **Skill** | Agent 从任务中提炼的可复用方法论，含 SKILL.md + 附属文件，MinIO 存储 |
| **Tool** | Agent 可调用的外部能力（文件操作、Shell 命令、API 调用等） |
| **Sandbox** | 临时 Docker 容器，所有命令和文件操作在其中执行 |
| **Workspace** | 用户持久化工作目录，通过 MinIO 存储 + tmpfs 挂载 |
| **MCP** | Model Context Protocol，标准化的工具接入协议 |
| **RAGFlow** | 外部知识库检索服务 |
| **RLS** | Row Level Security，PostgreSQL 行级安全策略 |
| **Delegation** | 父智能体将子任务委派给子智能体执行 |
| **DAG** | 有向无环图，智能体之间的层次结构 |
| **SSE** | Server-Sent Events，服务端推送事件流 |
| **MQ / RocketMQ** | 消息队列，用于事件驱动的异步任务触发 |
| **pg_trgm** | PostgreSQL 三元组相似度扩展，支持模糊文本匹配 |
| **MinIO** | S3 兼容对象存储，用于文件和工作区持久化 |
