# 21 - 智能体网页产物（Webpage Artifact）

## 背景与目标

对话中，纯文本有时不足以讲清一件事（数据对比、流程说明、可视化报告等）。本功能让智能体在对话过程中可以**生成一个完整的 HTML 网页**，用户在聊天界面点击卡片即可在新标签页/内嵌面板中打开查看，类似 Claude 的 Artifacts。

### 典型场景

- 数据分析结果 → 生成带图表（ECharts/CDN 引入）的可视化报告页
- 方案对比 → 生成结构化的对比页面
- 教程/说明 → 生成排版精美的图文页面
- 简单交互演示 → 生成带 JS 交互的小工具页

## 需求范围

### 本期做（MVP）

1. **后端新增 `create_webpage` 工具**
   - 参数：`title`（网页标题）、`html`（完整 HTML 文档字符串）
   - `requires_sandbox=False`，走 direct handler（参照 `channels/file_send.py` 的模式）
   - handler 将 HTML 写入对象存储：`workspaces/{workspace_id}/webpages/{uuid}.html`，content-type 为 `text/html`
   - 返回 JSON 字符串：`{"url": "...", "title": "..."}`，经现有 `tool_result` 事件的 `preview` 字段透传给前端（注意控制在 10000 字符截断限制内）
   - 单页大小限制（如 1MB），超出拒绝

2. **网页可访问 URL（方案 B：独立源隔离）**
   - 现有 workspace 文件下载路由强制 `Content-Disposition: attachment`（下载而非打开），不可用
   - 新增网页访问路由 `GET /api/webpages/{id}`，以 `text/html` + `inline` 返回
   - **安全隔离（关键）**：HTML 是智能体生成的不可信内容。网页通过**独立子域/端口** serve（如 `pages.{domain}` / `pages.localhost`），与主站 cookie/localStorage 源隔离，防止 XSS 窃取主站 JWT
   - 不用 presigned URL（会过期导致历史卡片失效），访问路由需鉴权校验归属（见风险 4）

3. **前端网页卡片 + iframe 内嵌预览**
   - 在 `ToolCallCard.tsx` 分发器新增 `CreateWebpageCard` 分支：`toolCall.name === 'create_webpage'` 时解析 `result.preview` 中的 `{url, title}`
   - 卡片展示：网页图标 + 标题 + 「新标签页打开」按钮
   - **点击卡片在对话页内嵌预览**：右侧面板（或抽屉）中以 `<iframe sandbox="allow-scripts" src="{url}">` 渲染网页，可关闭/收起；iframe `sandbox` 属性与独立源形成双重隔离
   - 流式和历史消息两条路径都汇聚到 ToolCallCard，卡片本身只需改这一处；内嵌预览面板挂在聊天页层级

4. **提示词引导**
   - Agent 系统提示中说明该工具的使用场景与约束（单文件、CDN 可用、不得引用本地资源）

### 本期不做（后续迭代）

- 网页版本管理/迭代更新（同一网页多次修改）
- React/多文件工程产物
- 网页分享给外部用户（公开链接）

## 技术方案要点

| 层 | 改动 | 位置 |
|---|---|---|
| 工具定义 | 新增 `create_webpage` Tool | `tools/builtin.py` |
| 工具 handler | HTML → MinIO，返回 `{url, title}` JSON | 新建 `artifacts/webpage.py`，`interface/api.py` 注册 direct handler |
| 访问路由 | `GET /api/webpages/{id}` 以 `text/html` inline 返回，鉴权校验归属 | 新路由文件 |
| 独立源 serve | 网页响应走独立子域/端口（`pages.{domain}`），与主站隔离 | 部署/CORS 配置 + 上述路由 |
| 前端卡片 | `CreateWebpageCard` + 分发分支 | `components/chat/ToolCallCard.tsx` |
| 内嵌预览 | iframe 预览面板（`sandbox="allow-scripts"`），点击卡片在对话页右侧展开 | 聊天页新增面板组件 |

**不改**：SSE 协议、`agent.py`、ChatPage 事件 switch——网页卡片复用现有 `tool_call`/`tool_result` 通道。

## 关键风险

1. **XSS 隔离**：独立子域 serve + iframe `sandbox="allow-scripts"`（不授 `allow-same-origin`）双重隔离，这是本功能最大的安全点
2. **URL 过期**：不用 presigned URL，用应用内鉴权路由，历史消息卡片长期有效
3. **大小与截断**：`tool_result` preview 有 10000 字符截断，handler 返回值必须短小（只放 url+title，不放 HTML 本体）
4. **多租户隔离**：网页文件按 workspace/user 归属存储，访问路由需校验归属，不能凭 URL 直接访问他人网页
5. **独立源下的鉴权**：子域与主站 cookie 隔离后，iframe 内请求无法携带主站登录态 → 网页 URL 需带一次性/限时访问令牌（query token），由后端校验令牌 + 归属，而不是依赖 cookie
