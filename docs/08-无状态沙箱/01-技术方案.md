# Stateless Sandbox + MinIO Workspace 技术方案

> **目标**：消除沙箱对 Docker volume 的依赖，所有文件持久化到 MinIO，沙箱完全无状态可水平扩展。

---

## 一、现状问题

```
当前架构：

  User Session 1 ──┐
                    ├──→ Docker volume "aio_workspace_{user_id}" ──→ 宿主机磁盘
  User Session 2 ──┘

问题：
  1. Docker volume 绑定宿主机 → 无法多节点部署
  2. 同一用户所有 session 共享 volume → 项目文件互相干扰
  3. 每个 session 独立容器 → 资源浪费（N session = N 容器）
  4. 每个容器从零开始 → pip install 重复执行
  5. 无 HTTP 文件上传/下载接口
```

## 二、最终设计：Per-user 容器 + 子文件夹隔离 + MinIO 持久化

### 2.1 核心理念

```
1 个用户 = 1 个长期存活的容器（懒创建）
容器内部用子文件夹实现 agent/session 级别的文件隔离
文件通过 MinIO 持久化，容器可随时销毁和恢复
```

### 2.2 容器内部结构

```
/workspace/
├── shared/                    ← 所有 agent/session 共享
│   ├── .venv/                 ← 共享 Python 虚拟环境
│   ├── node_modules/          ← 共享 npm 包
│   └── ...                    ← 用户安装的全局工具
│
├── {agent_id_1}/              ← Agent A 的工作目录
│   ├── src/
│   ├── data/
│   └── ...
│
├── {agent_id_2}/              ← Agent B 的工作目录
│   └── ...
│
└── sessions/
    └── {session_id}/          ← 无 agent 的 session 目录
        └── ...
```

### 2.3 数据关系

```
User (1) ──→ Container (1) ──→ MinIO: workspaces/{user_id}/files/...
                │
                ├── shared/         (跨 agent 共享)
                ├── {agent_1}/      (agent 级别隔离)
                ├── {agent_2}/
                └── sessions/{s1}/  (session 级别隔离)
```

## 三、容器生命周期

### 3.1 创建时机：懒加载

容器**不是**在用户注册或发消息时创建，而是在**第一次需要沙箱时**创建：

```
用户发消息 "你好"
  → LLM 回复文本 → 不碰沙箱 → 不创建容器 ✓

用户发消息 "帮我写个脚本"
  → LLM 返回 tool_call: write_file(...)
  → ToolExecutor._execute_in_sandbox()
  → SandboxManager.get_or_create(user_id)
  → 如果容器不存在 → 创建容器 → 从 MinIO 注入文件
  → exec_run: write_file → 写入 /workspace/{agent_id}/script.py
```

### 3.2 销毁时机：不活跃超时

```
容器创建后开始计时
  ↓
每次 exec_run 执行 → 刷新 last_active_at
  ↓
后台任务每 60 秒检查：
  if (now - last_active_at) > idle_timeout (默认 30 分钟):
    1. extract_and_sync → 将 /workspace 同步到 MinIO
    2. container.stop() + container.remove()
    3. 从 _active 字典中移除
  ↓
下次用户触发沙箱工具时 → 重新创建 → 从 MinIO 恢复
```

### 3.3 恢复机制

```
容器被销毁后，用户再次触发沙箱：
  → get_or_create(user_id) → 发现不在 _active
  → _create(user_id)
     ├── docker.containers.run() → 新容器 (空 tmpfs /workspace)
     └── workspace_storage.inject_files(user_id)
            └── MinIO → tar/b64 → exec_run 解压到 /workspace
  → 所有文件恢复，包括 shared/.venv 等
  → 用户体验：无感知，像容器一直在
```

## 六、端到端流程

### 6.1 用户首次触发沙箱工具

```
Chat Route → AgentLoop → tool_call: write_file("hello.py", ...)
       ↓
ToolExecutor.execute(workspace_id=None)
       ├── _execute_in_sandbox()
       │      ↓
       │   SandboxManager.get_or_create(user_id)
       │      ├── _active 中不存在
       │      └── _create(user_id)
       │             ├── docker.containers.run(
       │             │     image="aio-agent/sandbox:latest",
       │             │     tmpfs={"/workspace": "500m", "/tmp": "512m"},
       │             │     mounts=[],    ← 无 Docker volume!
       │             │     ...安全参数...
       │             │   )
       │             ├── workspace_storage.inject_files(sandbox, user_id)
       │             │      ├── list MinIO: workspaces/{user_id}/files/**
       │             │      ├── 如果为空 → 跳过 (首次使用)
       │             │      └── 如果有文件 → tar/b64/exec_run 注入
       │             └── 返回 Sandbox
       │
       ├── 计算 workdir:
       │      agent_id 存在 → /workspace/{agent_id}/
       │      无 agent_id  → /workspace/sessions/{session_id}/
       │
       └── exec_run: write hello.py → 写入对应 workdir
```

### 6.2 后续对话复用容器

```
用户再发消息 "运行一下"
       ↓
tool_call: run_shell("python hello.py")
       ↓
SandboxManager.get_or_create(user_id)
       ├── _active 中存在 → 直接返回
       └── 容器还在，上次写的文件还在
       ↓
exec_run: python hello.py → 输出结果
```

### 6.3 不同 Agent 使用同一容器

```
Session A (agent "代码助手", agent_id=aaa):
  → workdir = /workspace/aaa/
  → write_file("main.py") → /workspace/aaa/main.py

Session B (agent "数据分析", agent_id=bbb):
  → workdir = /workspace/bbb/
  → write_file("analysis.py") → /workspace/bbb/analysis.py

Session C (无 agent):
  → workdir = /workspace/sessions/{session_id}/
  → write_file("notes.txt") → /workspace/sessions/{session_id}/notes.txt

共享资源：
  Session A: pip install requests → 装到 /workspace/shared/.venv
  Session B: import requests → 直接可用 ✓
```

### 6.4 Delegation：子 agent 共享父 agent 的 workdir

```
父 agent (agent_id=aaa) delegate_task → 子 agent (agent_id=ccc)
  → 子 agent 共享父 session 的容器
  → workdir = /workspace/aaa/  (继承父 agent 的目录)
  → 子 agent 能读写父 agent 的文件 ✓
```

### 6.5 容器超时销毁 + 恢复

```
30 分钟无操作:
  → cleanup_idle() 检测到超时
  → extract_and_sync(sandbox, user_id)
     ├── tar /workspace → base64 → 读出
     ├── 逐文件比对 MinIO
     ├── 增量上传变更文件
     └── 更新 meta.json
  → container.stop() + container.remove()
  → _active 移除

用户回来:
  → get_or_create(user_id) → 不存在
  → _create(user_id)
     ├── 新容器 (空 tmpfs)
     └── inject_files(user_id) → 从 MinIO 恢复全部文件
  → 用户体验无感知
```

### 6.6 文件管理 API

```
浏览文件 (无需容器运行):
  GET /api/workspaces/{user_id}/files?path=shared
  → ObjectStorage.list("workspaces/{user_id}/files/shared/")
  → 返回文件列表

Presigned 下载:
  GET /api/workspaces/{user_id}/files/download?path=aaa/main.py
  → 返回 presigned URL → 浏览器直连 MinIO

Presigned 上传:
  POST /api/workspaces/{user_id}/files/upload
  body: { path: "aaa/main.py" }
  → 返回 presigned URL → 浏览器直传 MinIO

服务端上传 (小文件):
  POST /api/workspaces/{user_id}/files/content
  multipart: file + path
  → 服务端中转到 MinIO
```

## 七、SandboxManager 核心变更

### 7.1 对比

| 维度 | 现有 | 改为 |
|------|------|------|
| 容器粒度 | per (user, session) | **per user** |
| `_active` key | `{workspace_id}:{session_id}` | **`{user_id}`** |
| `/workspace` | Docker named volume | **tmpfs (无状态)** |
| workdir | 固定 `/workspace` | **`/workspace/{agent_id}/`** 或 **`/workspace/sessions/{session_id}/`** |
| 创建时机 | session 首次工具调用 | **用户首次工具调用 (懒加载)** |
| 销毁时机 | session TTL 过期 | **不活跃超时 (默认 30 分钟)** |
| 文件持久化 | Docker volume (宿主机) | **MinIO (对象存储)** |
| 文件注入 | 无 | **创建时 inject_files()** |
| 文件提取 | 无 | **销毁前 extract_and_sync()** |
| 定期同步 | 无 | **每 5 分钟增量同步** |
| 环境共享 | 无 (每 session 从零开始) | **shared/ 目录跨 agent 共享** |

### 7.2 get_or_create 逻辑

```python
async def get_or_create(self, user_id: str) -> Sandbox:
    key = user_id  # per-user 容器

    if key in self._active:
        sandbox = self._active[key]
        sandbox.last_active_at = datetime.utcnow()  # 刷新活跃时间
        return sandbox

    # 创建新容器
    sandbox = await self._create(user_id)
    self._active[key] = sandbox
    return sandbox
```

### 7.3 _create 逻辑

```python
async def _create(self, user_id: str) -> Sandbox:
    container = docker.containers.run(
        image=...,
        tmpfs={"/workspace": "500m", "/tmp": "512m"},
        mounts=[],  # 无 Docker volume
        ...安全参数...
    )
    sandbox = Sandbox(container_id=..., user_id=user_id, last_active_at=now)

    # 从 MinIO 恢复文件
    if self._workspace_storage:
        await self._workspace_storage.inject_files(self, sandbox, user_id)

    # 创建共享目录结构
    await self.execute(sandbox, "mkdir -p /workspace/shared /workspace/sessions")

    return sandbox
```

### 7.4 不活跃清理

```python
async def cleanup_idle(self, idle_seconds: int = 1800) -> int:
    """销毁不活跃的容器。返回销毁数量。"""
    destroyed = 0
    now = datetime.utcnow()
    for key, sandbox in list(self._active.items()):
        idle = (now - sandbox.last_active_at).total_seconds()
        if idle > idle_seconds:
            await self.destroy(sandbox, sync=True)
            destroyed += 1
    return destroyed
```

## 八、ToolExecutor workdir 路由

### 8.1 核心变更

所有沙箱工具的 exec_run 不再固定 workdir 为 `/workspace`，而是根据上下文路由：

```python
async def _execute_in_sandbox(self, tool_name, args, user_id, session_id,
                               workspace_id, agent_id):
    sandbox = await self.sandbox_mgr.get_or_create(user_id)

    # 计算 workdir
    if agent_id:
        workdir = f"/workspace/{agent_id}"
    else:
        workdir = f"/workspace/sessions/{session_id}"

    # 确保目录存在
    await self.sandbox_mgr.execute(sandbox, f"mkdir -p {workdir}")

    # 在对应 workdir 下执行
    if tool_name == "run_shell":
        command = args.get("command", "")
        result = await self.sandbox_mgr.execute(sandbox, f"bash -c {repr(command)}", workdir=workdir)
    elif tool_name == "write_file":
        path = args["path"]
        # 写入 workdir 下的相对路径
        full_path = f"{workdir}/{path}"
        ...
```

### 8.2 SandboxManager.execute 支持 workdir

```python
async def execute(self, sandbox, command, timeout=None, workdir="/workspace"):
    exec_result = container.exec_run(
        ["bash", "-c", command],
        workdir=workdir,  # 支持动态 workdir
        user="sandbox",
        ...
    )
```

### 8.3 路径安全

Agent 操作的 `path` 参数始终是**相对于 workdir** 的：

```
write_file("src/main.py")
  → agent 有 agent_id → 写入 /workspace/{agent_id}/src/main.py
  → 无 agent_id       → 写入 /workspace/sessions/{session_id}/src/main.py

run_shell("pip install requests")
  → workdir = /workspace/{agent_id}/
  → 但 pip install 到 /workspace/shared/.venv 需要用户/Agent 显式指定
  → 或者在 system prompt 中告知 Agent shared/ 目录的用途
```

**路径穿越保护**：仍然只允许 `/workspace` 下的路径，但不限制子目录。

## 九、文件同步协议

### 9.1 注入 (MinIO → 容器)

```
MinIO                              容器
  │                                  │
  list(workspaces/{user_id}/files/)  │
  → 文件清单                         │
  │                                  │
  get(file_1) → bytes                │
  get(file_2) → bytes                │
  ...                                │
  │                                  │
  tar.gz 构建 (内存)                  │
  → base64 编码                      │
  → exec_run 写入容器 ──────────────→ base64 -d | tar xzf - -C /workspace
  │                                  │
  │                                  文件恢复完成
```

### 9.2 提取 (容器 → MinIO)

```
容器                                MinIO
  │                                   │
  tar czf /tmp/sync.tar.gz            │
    -C /workspace .                   │
  → base64 读出                       │
  → 内存解压                          │
  → 逐文件 hash 比对                   │
  │                                   │
  变更文件 ──→ put(key, data) ──────→ 更新
  新增文件 ──→ put(key, data) ──────→ 创建
  已删文件 ──→ delete(key) ─────────→ 删除
  │                                   │
  put(meta.json) ──────────────────→ 更新清单
```

### 9.3 定期同步 (安全网)

```python
async def _periodic_sync_loop(self, interval: int):
    while True:
        await asyncio.sleep(interval)  # 默认 5 分钟
        for user_id, sandbox in list(self._active.items()):
            await self._workspace_storage.extract_and_sync(self, sandbox, user_id)
```

## 十、WorkspaceService 简化

per-user 模型下，Workspace 不再是一等实体，而是直接以 user_id 为 key 管理文件：

```python
class WorkspaceService:
    """用户文件管理服务 — 基于 MinIO 的 per-user 文件空间。"""

    @staticmethod
    def list_files(user_id: str, path: str = "") -> list[FileEntry]:
        """从 MinIO 列出用户文件。"""

    @staticmethod
    def get_file(user_id: str, path: str) -> bytes:
        """下载单个文件。"""

    @staticmethod
    def put_file(user_id: str, path: str, content: bytes) -> None:
        """上传单个文件。"""

    @staticmethod
    def delete_file(user_id: str, path: str) -> None:
        """删除单个文件。"""

    @staticmethod
    def presign_download(user_id: str, path: str) -> str:
        """生成下载 URL。"""

    @staticmethod
    def presign_upload(user_id: str, path: str) -> str:
        """生成上传 URL。"""

    @staticmethod
    def get_stats(user_id: str) -> dict:
        """获取文件统计 (数量、大小)。"""
```

## 十三、镜像构建与发布

本地开发时，沙箱镜像 `aio-agent-platform/sandbox:latest` 不会在 `docker compose up` 时自动构建（使用了 `profiles: ["build"]`），需要手动构建：

```bash
# 在项目根目录执行
docker compose --profile build build sandbox-build
```

如果不执行此步骤，首次触发沙箱工具时 Docker 会尝试从远程仓库拉取该镜像，但 Docker Hub 上不存在此镜像，导致 403 错误。

```text
Error deploying files: 500 Server Error
→ "failed to resolve reference 'docker.io/aio-agent-platform/sandbox:latest': 403 Forbidden"
```

构建完成后可通过以下命令验证：

```bash
docker images aio-agent-platform/sandbox:latest
```

生产发布时，Backend CI 会同时构建并推送 backend 和 sandbox 镜像到 GHCR 与阿里云 ACR。生产 `docker-compose.yml` 中的一次性 `sandbox-image` 服务会在 backend 启动前将沙箱镜像预拉取到宿主机 Docker daemon，供 backend 通过 Docker socket 创建短命容器。

如果 Linux 部署机报错 `docker-credential-desktop not installed`，说明其 `~/.docker/config.json` 遗留了 Docker Desktop 的全局 credential store 配置。删除其中的 `"credsStore": "desktop"` 后，重新登录 ACR 并拉取：

```bash
docker logout crpi-yvha9coypdedaafa.cn-beijing.personal.cr.aliyuncs.com
docker login crpi-yvha9coypdedaafa.cn-beijing.personal.cr.aliyuncs.com
docker compose pull
docker compose up -d
```


## 十六、风险与缓解

| 风险 | 影响 | 缓解 |
|------|------|------|
| 容器崩溃丢失未同步文件 | 最多丢 5 分钟数据 | 定期同步 (5min) |
| 大 workspace 恢复慢 | 容器创建延迟 | 增量同步 + 大小限制 (500MB) |
| MinIO 不可用 | 文件无法恢复 | 空 workspace 启动 + 重试 |
| 并发 session 写 shared/ | 数据冲突 | 串行对话 + 文件锁 (后期) |
| 容器长期不销毁 | 资源占用 | idle timeout (30min) |
| 多节点部署时容器不在当前节点 | 需要重新创建 | MinIO 恢复，无状态 |
