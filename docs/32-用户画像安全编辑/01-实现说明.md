# 用户画像安全编辑

用户画像保存在 `user_profiles.personal_portrait`，按用户与租户隔离，独立于 L1/L2/L3 记忆。画像用于描述角色、偏好、沟通风格和长期目标，并注入每轮对话的系统提示词。

## 工具调用

先调用 `read_user_portrait`，参数为 `{}`，返回当前执行租户中当前用户的完整 Markdown 画像；没有画像时返回空字符串。随后调用 `update_user_portrait`，必须显式传入 `operation`，且只传该操作对应的字段。

| operation | 必需字段 | 行为 |
| --- | --- | --- |
| `create` | `portrait` | 首次创建；非空画像已存在时拒绝 |
| `append` | `portrait` | 仅追加新增内容，必要时自动插入一个换行；画像为空时要求先创建 |
| `replace` | `old_str`、`new_str` | 精确且唯一匹配原文后替换；`new_str` 可为空以删除局部内容 |
| `clear` | `expected_portrait` | 预期全文与当前画像一致才清空 |
| `overwrite` | `expected_portrait`、`portrait` | 预期全文一致才执行明确的全文重写 |

常规修改使用 `replace`，例如：

```json
{
  "operation": "replace",
  "old_str": "- 职业：前端开发",
  "new_str": "- 职业：全栈开发"
}
```

找不到原文或匹配多处（包括重叠匹配）时拒绝操作；应重新读取最新画像、补充定位上下文后再编辑。不能改用 `overwrite` 绕过冲突。只有用户明确要求清空或全文重写时才选择相应操作。

旧的 `{ "portrait": "全文" }` 调用不再接受。空 `portrait`、缺少字段、错误类型、无关字段及 NUL 字符都会在访问数据库之前被拒绝；局部替换也不能隐式清空整份画像。使用工具白名单的智能体应同时启用 `read_user_portrait` 和 `update_user_portrait`。

## 并发与权限

每次调用都要求已绑定的执行租户上下文，并重新检查用户启用状态、租户启用状态和实际成员资格。运行中切换界面租户不会改变画像归属，也不会写回 `users.tenant_id`。

更新使用数据库条件更新，将读取的原文作为写入条件。读取后其他会话或设置页面已修改画像时，本次更新返回失败，要求重新读取。并发首次创建通过用户与租户联合主键检测冲突。每次成功修改前的非空画像以 `source="ai"` 存入 `portrait_versions`；历史快照与画像修改在同一事务提交。内容没有变化时不增加历史快照。

该保护覆盖工具在读写间遇到其他写入的情况。设置页面及历史版本恢复仍使用现有的人工全文保存接口；人工页面的过期表单提交不具备本工具的预期原文校验。

## 当前对话生效

默认提示词和智能体自定义提示词都使用独立标记包围画像，并以 JSON 字符串封装正文，避免正文中的 Markdown 标题或类似标记干扰更新。

一批工具执行完成后，若画像读取或修改成功，AgentLoop 会再从数据库读取一次最新画像，同时刷新实例提示词及当前消息中的系统提示。并行工具结果的排列顺序不能代表事务提交顺序，因此不会直接按工具结果顺序覆盖画像上下文。读取刷新失败时记录日志并保留原有上下文。

## 验证

`backend/tests/test_portrait_tools.py` 覆盖创建、追加、替换、局部删除、清空、全文重写、参数错误无写入、歧义匹配、历史快照、租户切换、权限撤销、上下文恢复和下一次模型请求中的画像刷新。标记为 `postgres` 的用例使用真实数据库并发执行两个基于相同原文的写入，验证只有一个成功，另一个收到冲突，且不生成失败写入的历史快照。

本功能不增加表或迁移，不修改已有画像内容。
