# 页内界面操作 - 技术方案

## Context

需求见 `docs/22-页内界面操作/01-需求文档.md`：让宠物/智能体操作用户当前浏览器页面，全程虚拟光标可视。

平台现状恰好具备实现所需的全部基础设施：

- **SSE 流式通道**：`chat_stream`（`interface/routes/chat.py`）将 `AgentLoop.run()` 的字符串事件与 `event_queue` 事件转发到前端。
- **阻塞-回包模式**：`AskUserQuestion` 已验证可行——`AgentLoop._run_ask_user_flow()` 在循环内直接拦截工具调用（不走 `tool_executor`，否则死锁），经 `event_queue` 推送 `confirmation_required` 事件，`yield "confirmation_flow:{id}:waiting"` 让 SSE generator drain 队列，然后 `asyncio.Event.wait()` 阻塞，前端通过 `POST /api/confirmations/{id}/respond` 回包唤醒。**前端工具执行复用同一模式**。
- **工具系统**：`tools/registry.py` 的 `Tool` dataclass（name/description/parameters/permission_level/timeout）+ `AgentLoop` 主循环的 tool_call 分发。
- **前端**：`chatApi.stream`（`lib/api.ts`）解析 SSE，`AgentChatPage.tsx` 大 switch 分发事件，`PetWidget` 全局悬浮（`AppLayout.tsx`），`petStore` 管理宠物状态。

**不引入 CopilotKit**（自带运行时与现有 SSE/工具体系重叠），自研协议 + 借鉴 AgentLens 的光标可视化思路。

---

## 1. 架构总览

```
LLM 输出 tool_call: ui_click {target: "agent-create-button"}
        │
        ▼
AgentLoop 主循环拦截（execution_location == "frontend"，不进 tool_executor）
        │
        ├── UiActionManager.create_action(session_id, tool_call_id, action, args)
        ├── event_queue.put({"type": "ui_action_required", ...})
        ├── yield f"ui_action:{tc.id}:waiting"     ← 让 SSE drain event_queue
        ├── await ui_action_manager.wait_for_result(action_id)  ← asyncio 阻塞（带超时）
        │
        ▼ SSE                                    ▼ 前端
chat_stream 转发 ui_action_required ──► AgentChatPage switch 分发
                                           │
                                           ▼
                              FrontendActionRegistry.execute(action, args)
                                           │
                    ┌──────────────────────┼──────────────────────┐
                    ▼                      ▼                      ▼
             VirtualCursor 移动      spotlight 高亮          真实 DOM 操作
             (宠物位置→目标)        (描边+气泡说明)         (router.push/click/fill)
                                           │
                                           ▼
                    POST /api/ui-actions/{action_id}/respond {status, result}
                                           │
        ◄──────────────────────────────────┘
wait_for_result 唤醒 → 结果作为 tool_result 注入 messages → Agent 继续 ReAct
```

### 关键决策

| 决策点 | 选择 | 理由 |
|---|---|---|
| 执行位置标记 | `Tool` 增加 `execution_location: str = "sandbox"`（取值 `sandbox|frontend`） | 一处元数据，AgentLoop 统一拦截 |
| 拦截方式 | 仿 `AskUserQuestion`：AgentLoop 主循环内直接拦截，不进 tool_executor | 阻塞等待会卡死 event_queue drain（已有教训，见 `interaction/handlers.py` 注释） |
| 状态存储 | 内存 `UiActionManager`（仿 `ConfirmationManager`），不落库 | 动作是瞬态的，会话结束即失效 |
| 回包通道 | REST `POST /api/ui-actions/{action_id}/respond` | 与 confirmations 一致，SSE 只下行 |
| LLM 感知页面 | 系统提示词注入"当前页面+可用动作清单" + `ui_read_screen` 工具兜底 | 避免每轮全量 DOM，token 可控 |
| 元素定位 | 语义定位符 `action_ref`（注册表键）为主，CSS 选择器为辅 | 选择器脆弱；注册表 ref 稳定且可控 |

## 2. 后端设计

### 2.1 Tool 元数据扩展（`tools/registry.py`）

```python
@dataclass
class Tool:
    name: str
    description: str
    parameters: dict
    requires_sandbox: bool
    permission_level: str = "read"
    timeout: int = 60
    execution_location: str = "sandbox"   # 新增: "sandbox" | "frontend"
```

### 2.2 前端工具定义（`tools/builtin.py` 新增）

注册 5 个内置前端工具，`execution_location="frontend"`，`requires_sandbox=False`：

| 工具 | 参数 | permission_level | 说明 |
|---|---|---|---|
| `ui_navigate` | `{path: string}` | read | 前端路由跳转，path 限白名单（平台路由表） |
| `ui_click` | `{action_ref?: string, selector?: string, description: string}` | write | 点击已注册动作或标注元素；二选一定位 |
| `ui_input` | `{selector: string, value: string, description: string}` | write | 向输入框填值（逐字动画由前端负责） |
| `ui_scroll_to` | `{selector: string}` | read | 滚动到元素可见 |
| `ui_read_screen` | `{}` | read | 返回当前页面摘要：路由、标题、已注册动作清单（name/description/schema/risk）、可见操作元素 |

- `ui_click` 命中的元素若被注册表标记 `risk: "dangerous"`，**后端在拦截处先走 `AskUserQuestion` 确认流程**（复用 `_run_ask_user_flow`），用户批准后才下发 `ui_action_required`。
- 子智能体委派时 `allowed_tools` 默认不含 `ui_*`（父 Agent 显式授予才可用）。

### 2.3 UiActionManager（新建 `core/ui_action.py`）

仿 `core/confirmation.py` 的 `ConfirmationManager`，纯内存：

```python
@dataclass
class PendingUiAction:
    id: str                    # uuid
    session_id: str
    user_id: str
    tool_call_id: str          # 对应 LLM tool_call id
    action: str                # ui_navigate / ui_click / ...
    args: dict
    risk: str                  # read | write | dangerous
    event: asyncio.Event
    result: dict | None        # 前端回包
    created_at: datetime
    timeout_seconds: int = 60

class UiActionManager:
    async def create_action(...) -> PendingUiAction
    async def wait_for_result(action_id) -> dict   # asyncio.wait_for(event.wait(), timeout)
    def resolve(action_id, result) -> bool

ui_action_manager = UiActionManager()   # 全局单例
```

与 ConfirmationManager 的差异：`wait_for_result` **必须带 `asyncio.wait_for` 超时**（确认卡片可以等用户 5 分钟，前端动作不能无限挂——页面可能已关闭）。超时返回 `{"status": "error", "error": "timeout"}`。

### 2.4 AgentLoop 拦截（`core/agent.py`）

主循环现有 L588 拦截 `AskUserQuestion` 的位置，扩展为：

```python
tool_def = self.tool_registry.get(tc.name)
if tool_def and tool_def.execution_location == "frontend":
    async for evt in self._run_ui_action_flow(tc, ctx):
        yield evt
    continue
```

`_run_ui_action_flow(tc, ctx)`（仿 `_run_ask_user_flow`，L893）五步：

1. **危险确认**（仅 `risk == "dangerous"`）：先走确认流程，拒绝则直接构造 err 结果返回。
2. `ui_action_manager.create_action(...)`。
3. `event_queue.put({"type": "ui_action_required", "action_id", "tool_call_id", "action", "args", "risk", "description", "created_at"})`。
4. `yield f"ui_action:{tc.id}:waiting"` — 让 `chat_stream` drain event_queue（与 `confirmation_flow:` 相同，此事件不直接转发前端）。
5. `result = await ui_action_manager.wait_for_result(...)`，随后：
   - `event_queue.put({"type": "ui_action_resolved", "action_id", "tool_call_id", "status", "result"})`；
   - 结果存入 `self._last_ui_action_output[tc.id]`，主循环按现有 `tool_result:{id}:{name}:ok|err:{json}` 格式 yield，注入 messages 继续 ReAct。

**中断支持**：前端可发送 `{"status": "cancelled"}` 回包（用户按 Esc/停止按钮即调 respond 接口）。另提供 `POST /api/ui-actions/sessions/{session_id}/cancel_all`，SSE 断线/会话切换时由前端调用，将所有 pending 动作判为 cancelled，防止 Agent 挂到超时。

### 2.5 回包路由（新建 `interface/routes/ui_actions.py`）

仿 `routes/confirmations.py`：

- `POST /api/ui-actions/{action_id}/respond` — 请求体 `{status: "ok"|"error"|"cancelled", result?: dict, error?: string}`；校验 `action.user_id == user.id`。
- `GET /api/ui-actions/sessions/{session_id}/pending` — 页面刷新恢复（刷新后前端动作上下文已丢失，恢复回来的 pending 动作由前端立即以 `error: page_reloaded` 回包，让 Agent 感知而非干等）。
- `POST /api/ui-actions/sessions/{session_id}/cancel_all`。

### 2.6 页面上下文注入

- 前端在**每次路由变化/动作注册表变更**时，随下一条聊天消息的 `context` 字段（chat 接口已有）带上 `{page_path, page_title, actions: [{name, description, parameters, risk}]}`。
- 后端将该摘要写入本轮 system prompt 的 `## 当前页面` 段，引导 LLM 使用正确的 `action_ref`。
- 清单缺失或过期时 LLM 可主动调 `ui_read_screen` 获取最新。

## 3. 前端设计

### 3.1 动作注册表（新建 `lib/uiActions/registry.ts`）

```ts
interface UiActionDef {
  name: string                 // 如 "agents.open_create_modal"
  description: string          // 给 LLM 看的语义描述
  parameters: Record<string, unknown>  // JSON Schema
  risk: "read" | "write" | "dangerous"
  // 执行体。target 解析与操作都在 handler 内完成
  handler: (args: Record<string, unknown>) => Promise<unknown>
  // 可选：动作对应的页面锚点元素选择器，用于光标定位与 spotlight
  anchorSelector?: string
}

class FrontendActionRegistry {
  register(def: UiActionDef): () => void   // 返回注销函数，配合 useEffect 生命周期
  list(): UiActionDef[]
  get(name): UiActionDef | undefined
}
```

- **全局动作**（`AppLayout` 挂载时注册）：`ui_navigate`、`ui_read_screen`、各主导航项的 `nav.goto_*`。
- **页面动作**：页面组件 `useEffect` 注册、卸载注销。首批覆盖：智能体列表页（打开新建弹窗、填写名称）、知识库页、MCP 页、聊天页（新建会话）。
- `ui_click`/`ui_input` 的底层执行用原生 DOM API（`element.click()`、React 受控输入用 native setter + `input` 事件派发），**不执行任意 JS，不支持 eval**。

### 3.2 虚拟光标（新建 `components/ui-agent/VirtualCursor.tsx`）

借鉴 AgentLens 设计，自研精简版：

```
<VirtualCursor/>            fixed 定位，pointer-events: none，z-index 顶层
  ├── 光标图形（SVG 小箭头/小爪子，配合宠物主题）
  ├── <SpotlightOverlay/>   目标元素描边 + 四周暗化遮罩 + 气泡说明
  └── 点击涟漪 / 输入逐字动画
```

执行器 `lib/uiActions/runner.ts`：

```ts
async function runWithCursor(action: PendingUiActionPayload): Promise<UiActionResult> {
  const el = resolveTarget(action)              // action_ref → anchorSelector，或 selector
  if (!el) return { status: "error", error: "element_not_found" }
  await cursor.moveTo(centerOf(el))             // 起点 = PetWidget 当前坐标（petStore.loadPos）
  spotlight.highlight(el, action.description)
  await sleep(300)                              // 让用户看清目标
  const result = await registry.get(action.action).handler(action.args)
  cursor.ripple()                               // 点击涟漪
  return { status: "ok", result }
}
```

- **移动动画**：`requestAnimationFrame` + easeOutCubic，时长按距离 clamp(200ms, dist/1.5px·ms, 800ms)。
- **动作队列**：`ui_action_required` 事件入队串行执行（AgentLoop 本身顺序执行普通工具，队列主要防御并发边界）。
- **中断**：Esc 键与"停止"按钮置 `abortFlag`，当前动画立即停止，回包 `{status: "cancelled"}`；队列清空。

### 3.3 SSE 事件分发（`AgentChatPage.tsx`）

switch 新增两个 case（与 confirmation 处理同构）：

- `ui_action_required`：push 到 `streaming.uiActions`（含 actionOrder），聊天流中渲染 `UiActionCard`（复用 ToolCallCard 视觉：动作名、目标描述、执行中 spinner）；同时投递给 `runner` 队列执行，完成后调 `uiActionsApi.respond(action_id, result)`。
- `ui_action_resolved`：更新卡片状态（成功 ✓ / 失败 ✗ / 已中断）。

注意聊天页之外的其他页面也要能执行：runner 与 VirtualCursor 挂在 `AppLayout`（与 PetWidget 同级），SSE 事件经 `chatStore`/事件总线广播，不限于 AgentChatPage 内处理。

### 3.4 宠物联动

- `runner` 开始执行时 `petStore.reportEvent("tool_call", {tool: action.action})`，宠物切 `work` 动作；成功 `celebrate`、失败/中断 `sad`（复用 `docs/16-宠物系统/04` 的动作映射机制）。
- 光标起点取 `PetWidget` 的当前屏幕坐标（`loadPos` 已有持久化坐标），营造"宠物伸手点屏幕"的观感。
- `PetChatPanel` 走的也是 `chatApi.stream`，同样能收到 `ui_action_required` —— 事件处理抽成共享 hook `useUiActionEvents`，聊天页与宠物面板复用，避免两份 switch 再膨胀出第三份。

## 4. 协议与时序

### 4.1 SSE 事件（下行）

```json
{"type": "ui_action_required", "action_id": "uuid", "tool_call_id": "call_xxx",
 "action": "ui_click", "args": {"action_ref": "agents.open_create_modal"},
 "risk": "write", "description": "点击：新建智能体", "created_at": "..."}

{"type": "ui_action_resolved", "action_id": "uuid", "tool_call_id": "call_xxx",
 "status": "ok", "result": {...}, "resolved_at": "..."}
```

`chat_stream` 对 event_queue 的 drain 逻辑（`routes/chat.py` L1240-1248）原样适用，无需改造——新增事件类型随队列自动转发。

### 4.2 REST（上行）

```
POST /api/ui-actions/{action_id}/respond
{"status": "ok", "result": {"navigated_to": "/agents"}}
{"status": "error", "error": "element_not_found"}
{"status": "cancelled"}
```

### 4.3 异常时序

| 场景 | 行为 |
|---|---|
| 前端 60s 未回包 | `wait_for_result` 超时 → tool_result err(timeout)，Agent 继续 |
| 用户按 Esc | 前端立即 respond(cancelled)，Agent 收到"用户中断" |
| 页面刷新 | 前端恢复时拉 `pending` 接口，逐条 respond(error: page_reloaded) |
| SSE 断线重连 | 前端调 `cancel_all`，pending 全部判 cancelled |
| 路由已切换导致动作注销 | runner resolveTarget 失败 → respond(error: action_not_available) |
| dangerous 动作 | 先弹确认卡片，批准后光标才动；拒绝则 err(rejected) |

## 5. 安全设计

1. **不开放任意 JS 执行**：前端动作只能是注册表内 handler，`ui_click`/`ui_input` 的 selector 仅用于原生 click/fill，无 `eval`/`new Function`。
2. **navigate 白名单**：`ui_navigate` 的 path 校验平台路由表，防跳转钓鱼外链。
3. **dangerous 二次确认**：注册表 `risk` 标记 + 后端拦截确认，双保险。
4. **租户/用户隔离**：回包接口校验 `action.user_id == 当前用户`；pending 存内存，不跨会话泄露。
5. **子智能体隔离**：`allowed_tools` 默认不含 `ui_*`。
6. **prompt injection 缓解**：`ui_read_screen` 只返回结构化摘要（不含页面文本全文回传给 LLM 时可截断/过滤），降低页面内容注入指令的风险；dangerous 确认让用户始终在最后回路中。
