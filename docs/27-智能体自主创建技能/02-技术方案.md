# 智能体自主创建与修改技能 — 技术方案

> 日期：2026-09-22。本文描述本地实现及验证边界；业务环境迁移、部署及真实模型对话验收尚未执行。

## 1. 实现范围

增强已有 `create_skill`，新增 `update_skill`、`read_skill_file`，复用技能服务和管理页面。模型可创建正文及附件、读取原版本后局部修改；用户身份由执行器传入，模型不能指定所有者、公开范围、启用状态或验证结论。

模型工具、管理 API 和附件接口统一经过 `SkillService`，保存正文与附件的完整版本。前端编辑抽屉一次提交正文、附件新增替换及删除，避免分步保存产生半完成状态。

主要代码：

| 位置 | 职责 |
|---|---|
| `skills/contracts.py` | 内容、路径、文件大小与必要引用校验 |
| `skills/mutations.py` | 工具输入结构、身份上下文、持久化幂等回执 |
| `skills/service.py` | 归属校验、并发保护、版本快照、附件合并、检索和部署 |
| `skills/storage.py` | 不可变 ZIP 对象、目录保留、导入解析 |
| `skills/workspace.py` | 沙箱内文件安全读取与分块写入 |
| `skills/handlers.py` | 创建、修改、读取、部署及验证反馈工具 |
| `interface/routes/skills.py` | 管理 API、历史内容与历史 ZIP 下载 |
| `prompts/skill_authoring.j2` | 内置和自定义提示词共用的技能编写规则 |
| `frontend/src/pages/SkillDetailPage.tsx` | 管理端和 Portal 共用的详情与版本页面 |

## 2. 模型工具

### 2.1 创建

```json
{
  "name": "Excel 对账",
  "description": "比较两份流水并输出差异",
  "category": "general",
  "tags": ["对账"],
  "trigger_condition": "需要比较两份流水时使用",
  "content": "## 输入\n两份流水 CSV。\n## 步骤\n执行 scripts/check.py，传入两份流水路径。\n## 输出与检查\n输出差异清单，并核对总额。",
  "files": [
    {"path": "scripts/check.py", "source_path": "scripts/check.py"},
    {"path": "references/rules.md", "content": "按流水号匹配，保留未匹配项。"}
  ],
  "request_id": "create-reconciliation-1"
}
```

调用前必须实际生成 `source_path` 指定的文件；该路径相对于当前授权工作区。附件每项只能选择 `content` 或 `source_path`。正文最多 128 KiB，单附件最多 1 MiB，附件合计最多 10 MiB、50 个文件。

### 2.2 修改

先调用 `view_skill({"skill_id":"…","for_edit":true})`，取得版本、正文、元数据、文件列表和小型文本附件。较大文本使用 `read_skill_file` 的 `offset`、`limit` 分页读取；二进制返回元数据。修改示例：

```json
{
  "skill_id": "实际技能 UUID",
  "expected_version": 1,
  "content": "完整的新正文，包含输入、重复流水检查、对账步骤和输出检查点。",
  "files": [{"path": "scripts/check.py", "source_path": "scripts/check-v2.py"}],
  "change_summary": "增加重复流水检查，保留原模板",
  "request_id": "update-reconciliation-2"
}
```

未传字段保留；可选文本传空字符串表示清空，标签传 `[]` 表示清空。附件按 `path` 新增或替换，未列出附件保留原字节；删除必须显式提供 `remove_files`，不能在同一请求中既删除又替换相同路径。

修改要求 `expected_version` 和非空 `change_summary`。版本冲突返回最新版本，模型重新读取后再处理，不自动覆盖。

### 2.3 结果语义

成功结果包含 `success=true`、`status`、`skill_id`、`name`、`version`、`previous_version`、`files`、`verification`、`is_active`、`visibility`、`changes` 和 `url`。状态为 `created / existing / updated / unchanged`。

错误结果包含 `success=false`、`code`、`message`，必要时附 `errors` 或冲突详情。执行器同步设置工具失败状态；聊天卡片同时检查工具状态与业务结果，不根据工具名称或 HTTP 状态猜测成功。

## 3. 数据、并发与恢复

- `skills.provenance`：保留原创建来源，以及最近修改的用户、会话、实际智能体、调用标识、时间、摘要和文件增删改列表。旧记录不补造来源。
- `skills.verification`：默认为 `unverified`；与保存结果分离。
- `skill_versions.snapshot`：更新前的完整元数据、正文、文件清单、来源和验证状态。旧版 `object_key` 永不覆盖。
- `skill_mutations`：按 `(user_id, request_id)` 保存请求摘要和成功回执。工具请求 ID 包含会话范围；未提供显式 ID 时使用规范化参数摘要。

所有写入口使用同一用户级 PostgreSQL 事务 advisory lock，等待上限 5 秒。锁内重新读取最新版本，再校验 `expected_version`、同名冲突及完整内容。归一化名称使用 NFKC 和大小写折叠。同名同载荷复用已有记录；同名不同载荷拒绝覆盖。

工具先读取幂等回执，再读取工作区文件。成功响应丢失后重试不会重新读已删除的源文件，也不会再次递增版本。同一显式 ID 携带不同参数返回 `idempotency_conflict`。相同 `source_path` 的内容变化需要新的请求 ID 或新版本请求，不能复用已经完成的请求 ID。

ZIP 使用含随机标识的版本对象键。上传成功但数据库回滚时删除本次对象；清理失败记录对象键，便于排查。数据库提交后才返回成功。带附件时存储失败不降级为缺件技能；纯文本允许仅保存数据库内容并在下载时重建 ZIP。进程在上传后突然退出仍可能留下孤立对象，本期没有定时扫描回收器。

仅有实际变化才归档旧版并增加一次版本。历史包、正文及快照可按版本读取；旧数据原本缺少的历史元数据在页面标记缺失，不视为已恢复。

## 4. 文件、权限与发现

目标路径只能位于 `scripts/`、`references/`、`assets/` 下，允许内部子目录。拒绝绝对目标路径、越界、重复路径及非法字符。工作区来源必须属于当前用户，slug 与可信工作区一致；读取只接受普通文件，并使用 `O_NOFOLLOW` 逐层拒绝符号链接。

部署目录为 `/workspace/{workspace_slug}/skills/{skill_id}/v{version}/`。固定 Python 文件操作脚本通过引用后的 JSON 参数接收数据，不把模型路径直接插入 shell。较大文件分块写入，避免命令行参数长度限制。使用 `python` 或 `bash` 等解释器执行脚本，技能创建本身不执行附件。

搜索、正文、文件、历史下载均校验所有者；执行搜索和推荐过滤停用技能。`view_skill(for_edit=true)` 可读取本人停用技能以便修复，不部署或执行附件。修改保持原启用状态，不自动恢复停用技能。

对话提示合并相关个人技能与原有绑定技能，去重并受摘要数量限制，摘要包含 ID 和版本。两种来源共用同一额度：相关技能按匹配度优先占用前面的槽位，但至少保留一个槽位给绑定技能，绑定技能不再被命中的检索结果整批挤掉；主对话、委派和发布 API 共用相同选择逻辑。保存后的当前会话也可直接用返回的 ID 加载。仍保留智能体工具白名单，不自动给存量智能体开放创建、修改能力；配置页在未勾选任何工具时提示该智能体不受白名单限制，可调用全部内置工具，避免把“0 个工具”误读为不可用。

## 5. 验证状态

`report_skill_result` 的既有成功反馈仅计入使用记录，不自动变更为“验证通过”。验证必须额外提交 `version`、`evidence_tool_call_id`、`expected_output`，三项要么同时提供，要么都不提供：只提供其中一部分时返回 `invalid_arguments`，不再静默降级为纯使用反馈并计入成功。三项齐备时还须满足：

1. 证据来自同用户、同会话真实执行的 `run_shell` 或 `run_code`。
2. 工具参数包含本技能本版本的脚本路径，目标版本仍为当前版本。
3. 运行成功且实际输出包含声明的非空预期结果。

这是有限的样例输出检查，不是脚本语义或任意业务正确性的证明。证据仅保留在当前执行器有限缓存中；进程重启、跨执行器或证据过期时拒绝宣称通过，需重新运行。验证失败保留原因并停用技能。正文、描述、触发条件或附件更新后恢复“未验证”，原有停用状态保持。

## 6. 页面与接口兼容性

- 聊天创建/更新卡片显示名称、版本变化、附件数量、验证状态、范围、摘要和详情链接。
- `/skills/:skillId` 是独立受认证路由，普通 Portal 用户也能查看本人技能。
- 历史版本由 `?version=N` 定位；支持刷新、直接访问、浏览器前进后退及历史 ZIP 下载。
- 技能列表显示来源及验证状态，并展示创建智能体、来源会话入口与验证失败说明；旧记录显示“历史记录，来源未知”。来源会话跳转前重新通过会话 API 校验访问权限（列表与详情共用同一实现）。
- Portal 顶栏提供 `/portal/skills`“我的技能”入口，只读列出本人技能并可进入详情；创建与修改仍通过对话完成，不以进入管理后台为前提。
- 编辑抽屉将正文、附件与待删除列表一次提交；取消抽屉不会提前删除附件。编辑态与查看态都能标记移除附件，侧栏显示待移除清单并支持撤销。

管理 API 的更新请求现在必须携带 `expected_version`；旧客户端需要同步更新。批量附件上传在表单携带该字段，删除附件在查询参数携带该字段。管理端 JSON 附件支持 `content` 或 `content_base64`（二选一）；模型工具继续使用 `content` 或工作区 `source_path`。

新增历史包下载：`GET /api/skills/{skill_id}/versions/{version}/download`。技能写入错误返回结构化 `detail`：冲突/忙碌为 409，存储错误为 502，其余校验错误为 400；请求结构错误仍由 FastAPI 返回 422。

## 7. 迁移和启用

新迁移为 `d0e1f2a3b4c5`，父版本 `c9d0e1f2a3b4`。部署时先按项目流程执行迁移，再启动新版服务和前端：

```bash

uv run alembic upgrade head
```

具有非空工具白名单的智能体，按实际需求开启 `create_skill`、`update_skill`、`search_skills`、`view_skill`、`read_skill_file`；需要执行样例时另需现有执行工具与部署、结果反馈能力。发布版本的工具配置也需同步发布，不能只更改运行中的提示词。
